# セマンティック検索

このドキュメントでは、seekdbでセマンティックインデックス(Semantic Search)を使用して検索する方法について説明します。

:::tip
この機能は現在のバージョンでは実験的な機能であり、本番環境での使用は推奨されません。
:::

## 概要

セマンティック検索は、seekdbが組み込んでいる埋め込み（Embedding）機能を活用し、ベクトルインデックスの使用プロセスを大幅に簡素化します。これにより、ユーザーはベクトルの概念を意識することなく、保存したい生データ（例：テキスト）を直接書き込むだけで、seekdbが内部で自動的にそれをベクトルに変換してインデックスを作成します。検索時も同様に、元の検索内容を提供するだけで、seekdbが自動的に埋め込みを行いベクトルインデックスを検索するため、使い勝手が大幅に向上します。

埋め込みモデルのパフォーマンスオーバヘッドを考慮し、セマンティック検索では同期および非同期の2種類の埋め込み方式を提供しています。
* 同期モード：データ書き込み後すぐに埋め込みとインデックス作成が実行され、データのリアルタイム可視性が保証されます。
* 非同期モード：バックグラウンドタスクがデータの埋め込みとインデックス作成をバッチ処理する方式です。これにより書き込み性能が大幅に向上しますが、データの可視化に遅延が生じます。データの可視性に対する時間的要件に応じて、バックグラウンドタスクのトリガー周期を柔軟に設定できます。

また、セマンティックインデックスを作成したテーブルでも、ブルートフォース検索を実行できます。ブルートフォース検索とは、テーブル全体をスキャンして最も近い上位n行の正確な結果を得る方法です。

## 機能サポート

:::tip
この機能は現在のバージョンではHNSW/HNSW_BQインデックスのみをサポートしています。
:::

現在のバージョンでは、セマンティックインデックスの更新、削除、検索の使用構文、メモリ管理方法がHNSWシリーズのインデックスと完全に一致しています。インデックスの監視とメンテナンスプロセスもサポートしており、非同期モードでの増分リフレッシュ時には、データの埋め込みが追加でトリガーされます。

サポートされている機能は以下の通りです：

| モジュール | 機能点 | 説明 |
|------|--------|------|
| DDL | テーブル作成時のセマンティックインデックス作成 | テーブル作成時に、`VARCHAR`列にセマンティックインデックスを作成できます。 |
| DDL | 既存テーブルへのセマンティックインデックスの追加作成 | 既存のテーブルの`VARCHAR`列にセマンティックインデックスを作成できます。 |
| サーチ | `semantic_distance` 関数 | この関数に生データを渡してベクトル検索を実行します。 |
| サーチ | `semantic_vector_distance` 関数 | この関数にベクトルを渡して検索を実行します。使用方法は2通りあります。<ul><li>SQL文に`APPROXIMATE`/`APPROX`句が含まれる場合、ベクトルインデックスを使用して検索します。</li><li>`APPROXIMATE`/`APPROX`句が含まれない場合、全表スキャンによるブルートフォース検索を実行します。</li></ul> |
| DBMS_VECTOR | `REFRESH_INDEX` | 通常のベクトルインデックスと同じ方法で使用し、インデックスの増分更新および非同期モードでの埋め込みを実行します。 |
| DBMS_VECTOR | `REBUILD_INDEX` | 通常のベクトルインデックスと同じ方法で使用し、インデックスのフル再構築を実行します。 |

使用上の注意事項は以下の通りです：

* 同期モードでは、書き込みパフォーマンスが埋め込み処理のパフォーマンスに影響される可能性があります。非同期モードでは、データの可視性に遅延が生じます。
* 重複する検索のシナリオでは、AI関数サービス(AI Function Service)を使用して事前にクエリベクトルを取得し、毎回の検索ごとに埋め込み処理を行うことを避けることを推奨します。

## 前提条件

### 埋め込みモデルとエンドポイントの登録

セマンティックインデックスを使用する前に、埋め込み（Embedding）モデルとエンドポイントを登録する必要があります。以下は登録の例です：

```sql
CALL DBMS_AI_SERVICE.DROP_AI_MODEL ('ob_embed');
CALL DBMS_AI_SERVICE.DROP_AI_MODEL_ENDPOINT ('ob_embed_endpoint');

CALL DBMS_AI_SERVICE.CREATE_AI_MODEL(
'ob_embed', '{
    "type": "dense_embedding",
    "model_name": "BAAI/bge-m3"
}');

CALL DBMS_AI_SERVICE.CREATE_AI_MODEL_ENDPOINT (
'ob_embed_endpoint', '{
    "ai_model_name": "ob_embed",
    "url": "https://api.siliconflow.cn/v1/embeddings",
    "access_key": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "provider": "siliconflow"
}');
```

:::info
access_key を実際のAPI Keyに置き換えてください。BAAI/bge-m3 モデルのベクトル次元は1024なので、セマンティックインデックスを作成する際には dim=1024 を指定する必要があります。
:::

### セマンティック検索の手動有効化

パラメータ `_enable_semantic_index` を使用してセマンティック検索機能を有効にします。デフォルトでは無効です。

```sql
ALTER SYSTEM SET _enable_semantic_index = true;
```

## インデックス構文と説明

### 作成

意味インデックスは、**テーブル作成時の同時作成**と**後からの単独作成**の2つの方法をサポートしています。作成時には以下の点に注意してください：

* インデックスを作成する際は、`VARCHAR` 型の列を指定する必要があります。
* `model`、`sync_mode` パラメータは通常のベクトルインデックスでは設定できません。
* 後からインデックスを作成する場合のパラメータと説明は、テーブル作成時にインデックスを作成する場合と同じです。

<Tabs>
<TabItem value="create-table" label="テーブル作成時の同時作成" default>

`CREATE TABLE` ステートメントを使用して意味インデックスを作成できます。インデックスパラメータを通じて、バックグラウンドタスクを同期または非同期で開始します。同期モードでは、データ挿入時に `VARCHAR` データが自動的にベクトルデータに変換されます。非同期モードでは、定期的または手動でデータ変換が完了します。

構文は以下のとおりです：

```sql
CREATE TABLE table_name (
    column_name1 data_type1,
    column_name2 VARCHAR, -- テキスト列
    ...,
    VECTOR INDEX index_name (column_name2) WITH (param1=value1, param2=value2, ...)
);
```

</TabItem>
<TabItem value="create-index" label="後からの単独作成">

既存のテーブルの `VARCHAR` 列に意味インデックスを作成できます。インデックスを後から作成する際は、指定されたインデックスパラメータを通じて、同期または非同期のバックグラウンドタスクが開始されます。同期モードでは、既存のすべての `VARCHAR` データにベクトル埋め込みが実行されます。非同期モードでは、定期的または手動で埋め込みが完了します。

構文は以下のとおりです：

```sql
CREATE VECTOR INDEX index_name
ON table_name(varchar_column_name)
WITH (param1=value1, param2=value2, ...);
```

</TabItem>
</Tabs>

`param` パラメータの説明は以下のとおりです：

| パラメータ | デフォルト値 | 値の範囲 | 必須 | 説明 | 備考 |
|------|--------|----------|----------|------|------|
| `distance` |  | `l2`/`inner_product`/`cosine` | はい | ベクトル距離アルゴリズムのタイプを指定します。 | `l2` はユークリッド距離、`inner_product` は内積距離、`cosine` はコサイン距離を表します。 |
| `type` |  | 現在 `hnsw` / `hnsw_bq` をサポートしています | はい | インデックスアルゴリズムのタイプを指定します。 |  |
| `lib` | `vsag` | `vsag` | いいえ | ベクトルインデックスライブラリのタイプを指定します。 | 現在VSAGベクトルライブラリのみをサポートしています。 |
| `model` |  | 登録済みのモデル名 | はい | エンベディングに使用する大規模言語モデルの名前を指定します。 | AI関数サービスでこのモデルを登録してから、インデックス作成時に使用する必要があります。:::tip 通常のベクトルインデックスでは、このパラメータの設定はサポートされていません。::: |
| `dim` |  | 正の整数、最大 4096 | はい | エンベディング後のベクトル次元数を指定します。 | モデルが提供する次元数と一致させる必要があります。 |
| `sync_mode` | `async` | `immediate` / `manual` / `async` | いいえ | データとインデックスの同期モードを指定します。 | `immediate` は同期モードを表し、`manual` は手動モードを表し、`async` は非同期モードを表します。:::tip 通常のベクトルインデックスではこのパラメータの設定はサポートされていません。:::
| `sync_interval` | `10s` | 時間間隔。例：`10s`、`1h`、`1d` など | いいえ | 非同期モードでバックグラウンドタスクをトリガーする周期を設定します。 | 数値部は正の数である必要があります。単位は秒（s）、時間（h）、日（d）などをサポートします。 |

その他のベクトルインデックスパラメータ（`m`、`ef_construction`、`ef_search` など）の使用方法は、通常のHNSW/HNSW_BQインデックスと同じです。詳細については、記事末尾の関連ドキュメントにあるHNSWシリーズインデックスのドキュメントを参照してください。

### サーチ

セマンティックインデックスは、以下の2種類の検索方式をサポートしています：

* 生のテキスト検索の使用
* ベクトル検索の使用
    * `APPROXIMATE`/`APPROX` 句を指定することで、ベクトルインデックスを使用した最近傍探索を実行できます。
    * `APPROXIMATE`/`APPROX` 句を指定しない場合、テーブル全体をスキャンするブルートフォース検索が実行されます。

<Tabs>
<TabItem value="text-search" label="生のテキスト検索の使用" default>

`semantic_distance` 式を使用し、生のテキストをベクトル検索に渡します。

構文は以下のとおりです：

```sql
SELECT ... FROM table_name
ORDER BY semantic_distance(column_name, 'query_text') [APPROXIMATE|APPROX]
LIMIT n;
```

ここで：
* `column_name`：セマンティックインデックス作成時に指定したテキスト列。
* `query_text`：検索対象の生のテキスト。
* `n`：返される結果行数。

</TabItem>
<TabItem value="vector-search" label="ベクトル検索の使用">

1. `APPROXIMATE` 句を含む場合：`semantic_vector_distance` 式を使用し、ベクトルを検索に渡します。検索ステートメントに `APPROXIMATE`/`APPROX` 句が含まれている場合、ベクトルインデックスを使用して検索が実行されます。構文は以下のとおりです：

    ```sql
    SELECT ... FROM table_name
    ORDER BY semantic_vector_distance(column_name, 'query_vector') [APPROXIMATE|APPROX]
    LIMIT n;
    ```

    ここで：
    * `column_name`：セマンティックインデックス作成時に指定したテキスト列。
    * `query_vector`：クエリベクトル。
    * `n`：返される結果行数。

2. `APPROXIMATE` 句を含まない場合：`semantic_vector_distance` 式を使用し、ベクトルを検索に渡して検索を実行します。`APPROXIMATE`/`APPROX` 句がない場合、テーブル全体をスキャンするブルートフォース検索が実行され、距離が最も近い上位 n 行の正確な結果が取得されます。検索実行時には、テーブルスキーマから `distance` の型を取得し、その後テーブル全体をスキャンします。各行に対してベクトル距離が計算されるため、正確な結果が保証されます。構文は以下のとおりです：

    ```sql
    SELECT ... FROM table_name
    ORDER BY semantic_vector_distance(column_name, 'query_vector')
    LIMIT n;
    ```
    パラメータの意味は `APPROXIMATE` 句を含む場合と同じです。

</TabItem>
</Tabs>

`APPROXIMATE`/`APPROX` 句の詳細な構文については、本文末の関連ドキュメントにあるHNSWシリーズのインデックスドキュメントを参照してください。

## 作成、更新、検索、削除の例

セマンティックインデックスのDML操作（`INSERT`、`UPDATE`、`DELETE`）は、通常のベクトルインデックスと完全に一致します。`VARCHAR`型のデータを挿入または更新する際、システムは`sync_mode`パラメータの設定に基づいて、ベクトル埋め込みを同期または非同期で実行します。

### テーブル作成時の作成

テストテーブル `items` を作成する際に `vector_idx` インデックスを作成します：

```sql
-- ob.embedモデルの作成は既に完了していることを前提とします（モデルの登録については「前提条件」セクションを参照してください）
CREATE TABLE items (
    id BIGINT PRIMARY KEY,
    doc VARCHAR(100),
    VECTOR INDEX vector_idx(doc)
    WITH (distance=l2, lib=vsag, type=hnsw, model=ob_embed, dim=1024, sync_mode=async, sync_interval=10s)
);
```

テストテーブル `items` に1件のデータを挿入すると、システムが自動的に埋め込みを行います：

```sql
INSERT INTO items(id, doc) VALUES(1, 'Rose');
```

### 事後作成

テストテーブル `items` を作成した後、`CREATE VECTOR INDEX` ステートメントを使用して `vector_idx` インデックスを作成します：

```sql
CREATE TABLE items (
    id BIGINT PRIMARY KEY,
    doc VARCHAR(100)
);

-- ob_embedモデルの作成は既に完了していることを前提とします（モデルの登録については「前提条件」セクションを参照してください）
CREATE VECTOR INDEX vector_idx
ON items (doc)
WITH (distance=l2, lib=vsag, type=hnsw, model=ob_embed, dim=1024, sync_mode=async, sync_interval=10s);
```

テストテーブル `items` に1件のデータを挿入すると、システムが自動的に埋め込みを行います：

```sql
INSERT INTO items(id, doc) VALUES(1, 'Rose');
```

### 更新

`VARCHAR` 型のデータを更新すると、システムが再埋め込みを行います：

* 同期モード：更新後すぐに再埋め込みを行います。
* 非同期モード：更新後、バックグラウンドタスクが次回のトリガー周期で再埋め込みを行います。

使用例：

```sql
UPDATE items SET doc = 'Lily' WHERE id = 1;
```

### 削除

削除操作は通常のベクトルインデックスと同じで、データを直接削除します。

使用例：

```sql
DELETE FROM items WHERE id = 1;
```

<TabItem value="text-search-example" label="原テキスト検索の使用" default>

```sql
-- ob_emb モデルの作成は事前に完了していることを前提とします。
CREATE TABLE items (
    id INT PRIMARY KEY,
    doc varchar(100),
    VECTOR INDEX vector_idx(doc)
    WITH (distance=l2, lib=vsag, type=hnsw, model=ob.embed, dim=1024, sync_mode=immediate)

INSERT INTO items(id, doc) VALUES(1, 'Rose');
INSERT INTO items(id, doc) VALUES(2, 'Sunflower');
INSERT INTO items(id, doc) VALUES(3, 'Rose');
INSERT INTO items(id, doc) VALUES(4, 'Sunflower');
INSERT INTO items(id, doc) VALUES(5, 'Rose');

-- 原テキストを使用した検索
SELECT id, doc FROM items
ORDER BY semantic_distance(doc, 'Sunflower')
APPROXIMATE LIMIT 3;
```

実行結果は次のとおりです：

```sql
+----+-----------+
| id | doc       |
+----+-----------+
|  2 | Sunflower |
|  4 | Sunflower |
|  5 | Rose      |
+----+-----------+
3 rows in set
```

</TabItem>
<TabItem value="vector-search-approx" label="ベクトル検索の使用（APPROXIMATE句付き）">

`semantic_vector_distance` 式を使用し、ベクトルを渡して検索を実行します。検索ステートメントに `APPROXIMATE`/`APPROX` 句が含まれている場合、ベクトルインデックスを使用して検索が行われます。

```sql
-- ob_emb モデルの作成は事前に完了していることを前提とします（モデルの登録については「前提条件」セクションを参照してください）。
CREATE TABLE items (
    id INT PRIMARY KEY,
    doc varchar(100),
    VECTOR INDEX vector_idx(doc)
    WITH (distance=l2, lib=vsag, type=hnsw, model=ob_embed, dim=1024, sync_mode=immediate)
);

INSERT INTO items(id, doc) VALUES(1, 'Rose');
INSERT INTO items(id, doc) VALUES(2, 'Lily');
INSERT INTO items(id, doc) VALUES(3, 'Sunflower');
INSERT INTO items(id, doc) VALUES(4, 'Rose');

-- クエリベクトルを取得する
SET @query_vector = AI_EMBED('ob_embed', 'Sunflower');

-- ベクトルを使用したインデックス検索
SELECT id, doc FROM items
ORDER BY semantic_vector_distance(doc, @query_vector)
APPROXIMATE LIMIT 3;
```

実行結果は次のとおりです：

```shell
+----+-----------+
| id | doc       |
+----+-----------+
|  3 | Sunflower |
|  1 | Rose      |
|  4 | Rose      |
+----+-----------+
3 rows in set
```
