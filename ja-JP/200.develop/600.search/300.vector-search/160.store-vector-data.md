# ベクトルデータの格納

このドキュメントでは、seekdbにおいて非構造化データ、半構造化データ、構造化データを統一的に格納する方法について説明します。これにより、seekdbの基本機能を最大限に活用するとともに、ハイブリッド検索を強力にサポートできます。

## グラフィズム

seekdbは異なるモダリティのデータを格納でき、ハイブリッド検索をサポートする原理は、テキスト、画像、動画などの異なるモダリティのデータをベクトルに統一的に変換し、ベクトル間の距離を計算することで検索を実現することです。ハイブリッド検索には2つの方式があります。単純検索は単一ベクトルの類似度検索に基づき、複雑検索はベクトルとスカラーのハイブリッド検索に関わります。

ベクトル検索自体には近似性があるため、実際の応用では精度を向上させるために様々な手法を組み合わせる必要があります。正確な検索結果こそが、ビジネスにより大きな価値をもたらすからです。

## ベクトルインデックスのメモリ設定

seekdbのベクトル検索では、[ob_vector_memory_limit_percentage](https://en.oceanbase.com/docs/common-oceanbase-database-10000000003453052)パラメータを設定してベクトルインデックスのメモリを制御します。

このパラメータのデフォルト値は`0`で、適応モードを意味します。システムがインスタンス内のベクトルインデックスデータのメモリ使用率を自動的に調整するため、手動での調整は不要です。

  * インスタンスの実メモリが8GB以下の場合、この値は`40`に自動設定されます。
  * インスタンスの実メモリが8GBを超える場合、この値は`50`に自動設定されます。

## ベクトル列の作成

以下の例では、ベクトルデータ、空間データ、リレーショナルデータを同一のテーブルに格納する方法を示しています。ベクトル列のデータ型は`VECTOR`であり、作成時に次元数を指定する必要があります。次元数は最大で16000までサポートされます。空間列のデータ型は`GEOMETRY`です。

```sql
CREATE TABLE t (
    -- リレーショナルデータ（構造化データ）の格納
    id INT PRIMARY KEY,
    -- 空間データ（半構造化データ）の格納
    g GEOMETRY,
    -- ベクトルデータ（非構造化データ）の格納
    vec VECTOR(3)
);
```

## `INSERT`ステートメントを使用したベクトルデータの挿入

`VECTOR`データ型の列を含むテーブルを作成すれば、`INSERT`ステートメントを直接使用してベクトルを挿入できます。データを挿入する際、ベクトルはテーブル定義時に指定した次元数と一致している必要があります。一致しない場合はエラーが発生します。この仕様により、データの一貫性とクエリの効率が保証されます。ベクトルの形式は標準的な浮動小数点数の配列で表され、各次元の値は有効な浮動小数点数でなければなりません。以下に簡単な例を示します。

```sql
INSERT INTO t (id, g, vec) VALUES (
  -- 構造化データの挿入
  1,
  -- 半構造化データの挿入
  ST_GeomFromText('POINT(1 1)'),
  -- 非構造化データの挿入
  '[0.1, 0.2, 0.3]'
);
```
