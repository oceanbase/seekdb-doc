# メモリベースの疎ベクトルインデックス

このドキュメントでは、seekdbのメモリベース疎ベクトルインデックスの作成、検索、および使用方法について説明します。

## 概要

メモリベースの疎ベクトルインデックスは、seekdbが疎ベクトルデータ（大部分の要素がゼロのベクトル）に対して提供する効率的なインデックスタイプです。メモリベースの疎ベクトルインデックスは、インデックスをメモリに完全にロードする必要がありますが、DMLとリアルタイム検索をサポートします。

疎ベクトルのクエリ性能を向上させるため、seekdbはVSAGアルゴリズムライブラリの疎ベクトルインデックス（SINDI）を統合しています。このインデックスはディスクベースの疎ベクトルインデックスよりも性能が優れており、メモリリソースに余裕がある場合に適しています。

## 機能サポート

メモリベースの疎ベクトルインデックスは、以下の機能をサポートしています。

| モジュール | 機能点 | 説明 |
|------|--------|------|
| DDL | テーブル作成時の疎ベクトルインデックス作成 | テーブル作成時に `SPARSEVECTOR` 列に疎ベクトルインデックスを作成できます。最大500,000次元をサポートします。 |
| DDL | 既存テーブルへの疎ベクトルインデックスの後付け | 既存のテーブルの `SPARSEVECTOR` 列に疎ベクトルインデックスを作成できます。最大500,000次元をサポートします。 |
| DML | 挿入、更新、削除 | 通常のベクトルインデックスと完全に同じDML操作構文です。 |
| サーチ | ベクトル検索 | SQL関数を使用した検索が可能です。 |
| サーチ | クエリパラメータ | 検索時に `parameters` 句を使用してクエリレベルのパラメータを設定できます。 |
| DBMS_VECTOR | `REFRESH_INDEX` | インデックスの増分更新を実行します。 |
| DBMS_VECTOR | `REBUILD_INDEX` | インデックスのフル再構築を実行します。 |

## インデックスのメモリ使用量の見積もりと実際の使用状況の確認

`DBMS_VECTOR`システムパッケージを使用してインデックスのメモリ使用量を見積もることができます。使い方は密ベクトルインデックスと同じです。ここでは、疎ベクトルインデックスに特有の要件についてのみ説明します。

* `IDX_TYPE`パラメータは`SINDI`に指定する必要があります。大文字小文字は区別されません。

## 作成構文と説明

メモリベースの疎ベクトルインデックスは、**テーブル作成時に同時作成する**方法と、**後から作成する**方法の2種類をサポートしています。作成時には以下の点に注意してください：

* 疎ベクトルインデックスを作成できる列の最大次元は500,000です。
* 疎ベクトルインデックスを作成するには、`SPARSEVECTOR`型の列を指定する必要があります。
* インデックスを作成する際には`VECTOR`キーワードを使用する必要があります。
* インデックスタイプは`sindi`を指定し、メモリベースの疎ベクトルインデックスを作成します。
* 距離アルゴリズムは`inner_product`（内積）のみをサポートします。
* 後からインデックスを作成する場合のパラメータと説明は、テーブル作成時にインデックスを作成する場合と同じです。

### テーブル作成時に同時作成する

`CREATE TABLE`ステートメントを使用して疎ベクトルインデックスを作成できます。

#### 構文

```sql
CREATE TABLE table_name (
    column_name1 data_type1,
    column_name2 SPARSEVECTOR,
    ...,
    VECTOR INDEX index_name (column_name2) WITH (param1=value1, param2=value2, ...)
);
```

#### パラメータ説明

| パラメータ | デフォルト値 | 値の範囲 | 必須 | 説明 | 備考 |
|------|--------|----------|----------|------|------|
| `distance` |  | `inner_product` | はい | ベクトル距離アルゴリズムのタイプを指定します。 | 疎ベクトルインデックスは、距離アルゴリズムとして内積（`inner_product`）のみをサポートしています。 |
| `type` |  | `sindi` | はい | インデックスアルゴリズムのタイプを指定します。 | メモリベースの疎ベクトルインデックスを作成することを示します。 |
| `lib` | `vsag` | `vsag` | いいえ | ベクトルインデックスライブラリのタイプを指定します。 | 現在、VSAGベクトルライブラリのみをサポートしています。 |
| `prune` | `false` | `true`/`false` | いいえ | ベクトルに対してプルーニングを実行するかどうかを指定します。 | `prune`が`true`の場合にのみ、`refine`および`drop_ratio_build`パラメータを設定する必要があります。`prune`が`false`の場合、全精度検索を提供できますが、`refine`を`true`に設定するか`drop_ratio_build`を`0`以外に設定するとエラーが発生します。 |
| `refine` | `false` | `true`/`false` | いいえ | 再配置が必要かどうかを指定します。 | 値が`true`の場合、検索結果に対して元の疎ベクトルを取得し、高精度の距離計算を実行して再配置します。これは、元のベクトルデータをもう一つ保存する必要があることを意味します。`prune=true`の場合にのみ設定できます。 |
| `drop_ratio_build` | `0` | `[0, 0.9]` | いいえ | 疎ベクトルデータのプルーニング比率を指定します。 | 新規に挿入された疎ベクトルは、値の大きさに応じて`query_length * drop_ratio_build`個の最小値が切り捨てられます。`refine`が`true`の場合は元のベクトルデータが保持され、そうでない場合は切り捨て後のデータのみが保持されます。`prune=true`の場合にのみ設定できます。 |
| `drop_ratio_search` | `0` | `[0, 0.9]` | いいえ | 検索される疎ベクトル値のプルーニング比率を指定します。 | 値が大きいほど、プルーニングが多くなり、精度が低下し、パフォーマンスが向上します。検索時に`parameters`句を使用して設定することもできますが、クエリパラメータの優先順位が高くなります。 |
| `refine_k` | `4.0` | `[1.0, 1000.0]` | いいえ | 再配置に参加する割合を示します。 | `limit_k * refine_k`件の結果を検索し、元のベクトルを取得して再配置します。`refine=true`の場合にのみ意味があります。検索時に`parameters`句を使用して設定することもできますが、クエリパラメータの優先順位が高くなります。 |

### 後からインデックスを作成する

既存のテーブルの`SPARSEVECTOR`列に対して、疎ベクトルインデックスを作成できます。

#### 構文

```sql
CREATE VECTOR INDEX index_name ON table_name(column_name) WITH (param1=value1, param2=value2, ...);
```

#### パラメータ説明

パラメータの説明は、テーブル作成時にインデックスを作成する場合と同じです。詳細は上記を参照してください。

## 作成・更新・削除の例

### テーブル作成時の作成

テストテーブル`sparse_t1`を作成し、疎ベクトルインデックスを作成します。

```sql
CREATE TABLE sparse_t1 (
    c1 INT PRIMARY KEY,
    c2 SPARSEVECTOR,
    VECTOR INDEX sparse_idx1(c2)
    WITH (lib=vsag, type=sindi, distance=inner_product)
);
```

テストテーブルに疎ベクトルデータを挿入します。

```sql
INSERT INTO sparse_t1 VALUES(1, '{1:0.1, 2:0.2, 3:0.3}');
INSERT INTO sparse_t1 VALUES(2, '{3:0.3, 2:0.2, 4:0.4}');
INSERT INTO sparse_t1 VALUES(3, '{3:0.3, 4:0.4, 5:0.5}');
```

テストテーブルを検索します。

```sql
SELECT * FROM sparse_t1;
```

実行結果は次のとおりです。
```
+----+---------------------+
| c1 | c2                  |
+----+---------------------+
|  1 | {1:0.1,2:0.2,3:0.3} |
|  2 | {2:0.2,3:0.3,4:0.4} |
|  3 | {3:0.3,4:0.4,5:0.5} |
+----+---------------------+
3 rows in set
```

### インデックスの後付け

テストテーブル作成後に疎ベクトルインデックスを作成します。

```sql
CREATE TABLE sparse_t2 (
    c1 INT PRIMARY KEY,
    c2 SPARSEVECTOR
);

CREATE VECTOR INDEX sparse_idx2 ON sparse_t2(c2)
WITH (lib=vsag, type=sindi, distance=inner_product,
      prune=true, refine=true, drop_ratio_build=0.1,
      drop_ratio_search=0.5, refine_k=2.0);
```

テストテーブルに疎ベクトルデータを挿入します。

```sql
INSERT INTO sparse_t2 VALUES(1, '{1:0.1, 2:0.2, 3:0.3}');
```

テストテーブルを検索します。

```sql
SELECT * FROM sparse_t2;
```

実行結果は次のとおりです。

```shell
+----+---------------------+
| c1 | c2                  |
+----+---------------------+
|  1 | {1:0.1,2:0.2,3:0.3} |
+----+---------------------+
1 row in set
```

### 更新

疎ベクトルデータを更新する際、インデックスは自動的にメンテナンスされます。

```sql
UPDATE sparse_t1 SET c2 = '{1:0.1}' WHERE c1 = 1;
```

### 削除

削除操作は通常のベクトルインデックスと同じで、データを直接削除します。

```sql
DELETE FROM sparse_t1 WHERE c1 = 1;
```

## サーチ

疎ベクトルインデックスのサーチ構文は密ベクトルインデックスと類似しており、`APPROXIMATE`/`APPROX` キーワードを使用して近似最近傍探索を行います。

### 構文

```sql
SELECT ... FROM table_name
ORDER BY inner_product(column_name, query_vector) [APPROXIMATE|APPROX]
LIMIT n [PARAMETERS(param1=value1, param2=value2)];
```

ここで、
* `column_name`：疎ベクトルインデックス作成時に指定した `SPARSEVECTOR` 列。
* `query_vector`：クエリベクトル。`'{1:2.4, 3:1.5}'` のような疎ベクトル形式の文字列です。
* `n`：返される結果行数。
* `PARAMETERS`：オプションのクエリレベルパラメータ。`drop_ratio_search` と `refine_k` を設定するために使用します。

### サーチ構文要件

* `APPROXIMATE/APPROX` キーワードを指定する必要があります。これにより、サーチはベクトルインデックスを使用し、テーブル全体のスキャンは行いません。
* `ORDER BY` と `LIMIT` 句を含める必要があります。
* `ORDER BY` は単一のベクトル条件のみをサポートします。
* `LIMIT + OFFSET` の取り得る範囲は `(0, 16384]` です。
* `LIMIT` 句を指定しない場合、エラーが発生します。

### 距離関数の使用規則

* `APPROXIMATE/APPROX` を指定し、現在のバージョンでサポートされている距離関数を呼び出し、かつそれがベクトルインデックスアルゴリズムとマッチする場合、サーチはベクトルインデックスを使用します。
* `APPROXIMATE/APPROX` を指定し、距離関数がベクトルインデックスアルゴリズムとマッチしない場合、サーチはベクトルインデックスを使用しませんが、エラーも報告しません。
* `APPROXIMATE/APPROX` を指定し、距離関数が現在のバージョンでサポートされていない場合、サーチはベクトルインデックスを使用せず、エラーが発生します。
* `APPROXIMATE/APPROX` を指定しない場合、現在のバージョンでサポートされている距離関数を呼び出します。サーチはベクトルインデックスを使用しませんが、エラーも報告しません。

### その他の説明

* `WHERE` 条件は、ベクトルインデックス検索のフィルタ条件として使用されます。
* リコール率は、ビルドパラメータと検索パラメータの影響を受けます。
* インデックスの検索パラメータは、インデックス作成時に設定できます。インデックス作成後に調整が必要な場合は、[DBMS_VECTOR.REBUILD_INDEX](../../../../../450.reference/300.pl/1000.pl-system-package/17850.dbms-vector/300.rebuild-index.md) を使用してテーブルレベルの属性を変更するか、クエリ時にクエリレベルパラメータ `ef_search` を指定して調整できます。

### 検索固有の要件

詳細な要件については、[密ベクトルインデックス](../300.dense-vector-index/100.dense-vector-index-overview.md) を参照してください。ここでは、疎ベクトルインデックスの特殊な要件のみを紹介します：

* クエリパラメータの優先順位：`PARAMETERS` で設定されたクエリレベルパラメータ > インデックス作成時に設定されたクエリパラメータ > デフォルト値。
* `drop_ratio_search`：取り得る範囲は `[0, 0.9]`、デフォルト値は `0` です。クエリの疎ベクトル値を剪枝する割合です。値が大きいほど、剪枝が多くなり、精度が低下し、パフォーマンスが向上します。値の大きさに応じて `query_length * drop_ratio_search` 個の最小値を剪枝します。すべてを剪枝することは意味がないため、少なくとも1つの値は保持されます。
* `refine_k`：取り得る範囲は `[1.0, 1000.0]`、デフォルト値は `4.0` です。リランキングに参加する割合を表します。クエリは `limit_k * refine_k` 個の結果を取得し、元のベクトルを取得してリランキングを行います。`refine=true` の場合にのみ有効です。

### 使い方

#### 通常のクエリ

```sql
CREATE TABLE t1 (
    c1 INT PRIMARY KEY,
    c2 SPARSEVECTOR,
    VECTOR INDEX idx1(c2)
    WITH (lib=vsag, type=sindi, distance=inner_product)
);

INSERT INTO t1 VALUES(1, '{1:0.1, 2:0.2, 3:0.3}');
INSERT INTO t1 VALUES(2, '{3:0.3, 2:0.2, 4:0.4}');
INSERT INTO t1 VALUES(3, '{3:0.3, 4:0.4, 5:0.5}');
INSERT INTO t1 VALUES(4, '{5:0.5, 4:0.4, 6:0.6}');
INSERT INTO t1 VALUES(5, '{5:0.5, 6:0.6, 7:0.7}');

SELECT * FROM t1
ORDER BY negative_inner_product(c2, '{3:0.3, 4:0.4}')
APPROXIMATE LIMIT 4;
```

実行結果は次のとおりです：

```shell
+----+---------------------+
| c1 | c2                  |
+----+---------------------+
|  2 | {2:0.2,3:0.3,4:0.4} |
|  3 | {3:0.3,4:0.4,5:0.5} |
|  4 | {4:0.4,5:0.5,6:0.6} |
|  1 | {1:0.1,2:0.2,3:0.3} |
+----+---------------------+
```

#### クエリパラメータの使用

```sql
SELECT *, negative_inner_product(c2, '{3:0.3, 4:0.4}')
AS score  FROM t1
ORDER BY score APPROXIMATE LIMIT 4
PARAMETERS(drop_ratio_search=0.5);
```

実行結果は次のとおりです：

```shell
+----+---------------------+---------------------+
| c1 | c2                  | score               |
+----+---------------------+---------------------+
|  4 | {4:0.4,5:0.5,6:0.6} | -0.1600000113248825 |
|  3 | {3:0.3,4:0.4,5:0.5} | -0.2500000149011612 |
|  2 | {2:0.2,3:0.3,4:0.4} | -0.2500000149011612 |
+----+---------------------+---------------------+
3 rows in set
```

## インデックスの監視とメンテナンス

メモリベースの疎ベクトルインデックスは、いくつかの監視ビューを提供しており、`DBMS_VECTOR`システムパッケージを使用したインデックスのメンテナンス（増分更新およびフル再構築を含む）もサポートしています。その使い方は密ベクトルインデックスと同じです。
