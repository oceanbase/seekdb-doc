# ベクトルインデックスのメモリ管理

このドキュメントでは、seekdbにおける**すべてのタイプのベクトルインデックス**のメモリ使用量を見積もり、管理する方法について説明します。

## ベクトルインデックスのメモリ設定

seekdbのベクトル検索では、[ob_vector_memory_limit_percentage](https://en.oceanbase.com/docs/common-oceanbase-database-10000000003453052)パラメータを設定してベクトルインデックスのメモリを制御します。

このパラメータのデフォルト値は`0`で、適応モードを意味します。つまり、システムがインスタンス内のベクトルインデックスデータのメモリ使用割合を自動的に調整し、手動での調整は不要です。
  * インスタンスの実際のメモリが8GB以下の場合、この値は`40`に自動設定されます。
  * インスタンスの実際のメモリが8GBを超える場合、この値は`50`に自動設定されます。

## インデックスメモリの見積もりと実際の使用量の確認

`DBMS_VECTOR`システムパッケージを使用してインデックスメモリを見積もることができます。

* テーブル作成前には、[INDEX_VECTOR_MEMORY_ADVISOR](../../../../450.reference/300.pl/1000.pl-system-package/17850.dbms-vector/500.index-vector-memory-advisor.md)プロシージャを使用してインデックスメモリを見積もります。
* テーブル作成済みでデータが挿入されている場合は、[INDEX_VECTOR_MEMORY_ESTIMATE](../../../../450.reference/300.pl/1000.pl-system-package/17850.dbms-vector/400.index-vector-memory-estimate.md)プロシージャを使用してインデックスメモリを分析します。

ベクトルインデックスのメモリ見積もりでは、2つの情報が返されます：ベクトルインデックス作成に必要な最小メモリ構成、およびHNSW_SQとIVFインデックス作成後の実際のメモリ使用状況です。

:::tip
メモリが疎なインデックスの場合、`IDX_TYPE`パラメータは必ず`SINDI`（大文字小文字を区別しない）に指定する必要があります。そうでない場合、メモリ見積もりは実行できません。
:::

実際のメモリ使用量の詳細は、ビュー[GV$OB_VECTOR_MEMORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004477919)または[V$OB_VECTOR_MEMORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004477877)から取得できます。

## インデックス再構築時のメモリ最適化

パーティションテーブルのベクトルインデックス再構築操作については、`vector_index_memory_saving_mode`構成パラメータを提供し、インデックス再構築時のメモリ使用量を制御できます。このモードを有効にすると、パーティションテーブルのベクトルインデックス再構築(rebuild)プロセス中のメモリ消費を削減できます。通常、ベクトルインデックスの再構築には、インデックスサイズの2倍に相当するメモリが消費されます。メモリ節約モードを有効にすると、システムはパーティションテーブルの各パーティションの構築が完了した後、そのパーティションのメモリインデックスを一時的に削除することでメモリを解放し、再構築操作に必要な総メモリを効果的に削減します。構文と例については、[vector_index_memory_saving_mode](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004478889)を参照してください。
