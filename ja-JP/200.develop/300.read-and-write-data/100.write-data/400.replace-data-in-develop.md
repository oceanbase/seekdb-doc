# データの置換

`REPLACE INTO` ステートメントを使用して、データの挿入または更新を行えます。本記事では、関連するステートメントの使い方と例を紹介します。

## データ置換の準備

テーブルデータを置き換える前に、以下の事項を確認してください：

* seekdbに接続されていることを確認してください。データベース接続操作については、[接続方法の概要](../../100.connect-to-seekdb/100.connection-methods-overview.md)を参照してください。

* 操作対象のテーブルに対する`INSERT`、`UPDATE`、`DELETE`権限が付与されていることを確認してください。現在のユーザー権限の確認に関する操作については、[ユーザー権限の確認](../../../400.guides/500.manage/300.security/300.access-control/200.user-and-permission/400.view-user-permissions.md)を参照してください。該当する権限がない場合は、管理者に連絡し権限の付与を依頼してください。ユーザー権限の付与に関する操作については、[直接権限の付与](../../../400.guides/500.manage/300.security/300.access-control/200.user-and-permission/200.direct-authority.md)を参照してください。

## データの置換

通常、テーブル内の1つまたは複数のレコードを置き換えるには、[REPLACE INTO](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002017054) ステートメントを使用します。

`REPLACE INTO` ステートメントの構文は以下のとおりです：

```sql
REPLACE INTO table_name VALUES(list_of_values);
```

|        パラメータ        | 必須    |     説明     |                 例                  |
|------------------|------|------------|-------------------------------------|
| table_name       | はい    | データを挿入するテーブルを指定します | table1                              |
| (list_of_values) | はい    | 挿入するデータ      | (1,'CN',2001, current_timestamp ()) |

`REPLACE INTO` ステートメントは、置き換えるデータとテーブルの主キーまたは一意キーに基づいて動作します：

* 主キーまたは一意キーとの競合がない場合、レコードを挿入します。

* 主キーまたは一意キーとの競合がある場合、既存のレコードを削除してから、新しい行を挿入します。

  :::info

  ターゲットテーブルには、主キーまたは一意インデックスを設定することを推奨します。設定しない場合、重複レコードが挿入されやすくなります。

  :::

### テーブルにデータレコードがない場合、またはデータレコードはあるが主キーまたは一意キーとの競合がない場合

テーブルにデータレコードがない場合、またはテーブルにデータレコードはあるが主キーまたは一意キーとの競合がない場合、`REPLACE INTO` ステートメントを使用してデータを置き換えることができます。結果は、`INSERT` ステートメントでデータを挿入した場合と同じになります。

例：

* `t_replace` テーブルを作成した後、`REPLACE INTO` ステートメントを使用して1行のデータを挿入します。

  ```sql
  CREATE TABLE t_replace(
      id number NOT NULL PRIMARY KEY
      , name varchar(10) NOT NULL
      , value number
      ,gmt_create timestamp NOT NULL DEFAULT current_timestamp
  );
  Query OK, 0 rows affected

  REPLACE INTO t_replace values(1,'CN',2001, current_timestamp ());
  Query OK, 1 row affected

  SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2025-12-23 15:04:08 |
  +----+------+-------+---------------------+
  1 row in set
  ```

  例の結果からわかるように、`t_replace` テーブルは作成後、データは挿入されていません。`REPLACE INTO` ステートメントを実行すると、テーブルに1件のレコードが挿入されます。

* 再度 `REPLACE INTO` ステートメントを使用して、1行のデータを挿入します。

  ```sql
  SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2025-12-23 15:04:08 |
  +----+------+-------+---------------------+
  1 row in set

  REPLACE INTO t_replace(id, name, value, gmt_create) VALUES(2,'US',2002,current_timestamp ());
  Query OK, 1 row affected

  SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2025-12-23 15:04:08 |
  |  2 | US   |  2002 | 2025-12-23 15:06:29 |
  +----+------+-------+---------------------+
  2 rows in set
  ```

  例の結果からわかるように、`t_replace` テーブルには既に1件のレコードが存在します。`(2,'US',2002,current_timestamp ())` のデータはテーブル内のレコードと一意性制約で競合しないため、実行結果として `t_replace` テーブルに1件のレコードが挿入されます。

* クエリステートメントを `REPLACE INTO` ステートメントの `VALUES` 句として使用し、複数のデータを挿入します。テーブル `t_insert` のデータをテーブル `t_replace` に挿入します。

  ```sql
  SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2025-12-23 15:04:08 |
  |  2 | US   |  2002 | 2025-12-23 15:06:29 |
  +----+------+-------+---------------------+
  2 rows in set

  SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  7 | EN   |  1007 | 2025-12-23 15:13:57 |
  |  8 | JP   |  1008 | 2025-12-23 15:14:14 |
  +----+------+-------+---------------------+
  2 rows in set

  REPLACE INTO t_replace
       SELECT id,name,value,gmt_create FROM t_insert;
  Query OK, 2 rows affected
  Records: 2  Duplicates: 0  Warnings: 0

  SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2025-12-23 15:04:08 |
  |  2 | US   |  2002 | 2025-12-23 15:06:29 |
  |  7 | EN   |  1007 | 2025-12-23 15:13:57 |
  |  8 | JP   |  1008 | 2025-12-23 15:14:14 |
  +----+------+-------+---------------------+
  4 rows in set
  ```

### テーブルにデータレコードが存在し、主キーまたは一意キーが競合する場合

テーブルにデータレコードが存在し、挿入するデータに主キーまたは一意キーの競合がある場合、`REPLACE INTO` ステートメントを使用すると、テーブル内の競合する既存データを削除し、新しいデータで置き換えることができます。

`t_replace` テーブルに1件のレコードを挿入する例を以下に示します：

```sql
SELECT * FROM t_replace;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   |  2001 | 2025-12-23 15:04:08 |
|  2 | US   |  2002 | 2025-12-23 15:06:29 |
|  7 | EN   |  1007 | 2025-12-23 15:13:57 |
|  8 | JP   |  1008 | 2025-12-23 15:14:14 |
+----+------+-------+---------------------+
4 rows in set

REPLACE INTO t_replace(id, name, value, gmt_create) VALUES(2,'EN',2002,current_timestamp ());
Query OK, 2 rows affected

SELECT * FROM t_replace;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   |  2001 | 2025-12-23 15:04:08 |
|  2 | EN   |  2002 | 2025-12-23 15:15:01 |
|  7 | EN   |  1007 | 2025-12-23 15:13:57 |
|  8 | JP   |  1008 | 2025-12-23 15:14:14 |
+----+------+-------+---------------------+
4 rows in set
```

この例では、テーブル `t_replace` の `id` 列は主キー列であり、一意性制約を満たす必要があります。挿入するデータ `(2,'EN',2002,current_timestamp ())` は一意性制約に違反するため、システムは元の行レコード `(2,'US',2002,current_timestamp ())` を削除し、新しい行レコードとして `(2,'EN',2002,current_timestamp ())` を挿入します。
