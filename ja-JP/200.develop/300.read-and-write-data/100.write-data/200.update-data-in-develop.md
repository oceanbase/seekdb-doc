# データの更新

テーブルにデータを挿入した後、`UPDATE` ステートメントやその他のステートメントを使用して、テーブルの行レコードを更新できます。本記事では、関連するステートメントの使い方と例を紹介します。

## データ更新の準備

テーブルデータを更新する前に、以下の事項を確認してください：

* seekdbに接続されていることを確認してください。データベース接続操作については、[接続方法の概要](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013253)を参照してください。

* 操作対象のテーブルに対する`UPDATE`権限を保有していることを確認してください。現在のユーザー権限に関する操作については、[ユーザー権限の確認](../../../400.guides/500.manage/300.security/300.access-control/200.user-and-permission/400.view-user-permissions.md)を参照してください。該当する権限がない場合は、管理者に連絡し権限の付与を依頼してください。ユーザー権限に関する操作については、[直接権限の付与](../../../400.guides/500.manage/300.security/300.access-control/200.user-and-permission/200.direct-authority.md)を参照してください。

## UPDATEステートメントを使用したデータの更新

通常、テーブルデータを更新するには、[UPDATE](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002017009) ステートメントを使用します。

`UPDATE` ステートメントの構文は以下のとおりです：

```sql
UPDATE table_name
SET column_name = value [, column_name = value]...
[ WHERE condition ];
```

|                      パラメータ                       | 必須   |                   説明                    |
|-----------------------------------------------|------|-----------------------------------------|
| table_name                                  | はい  | 更新対象のテーブルを指定します。                              |
| column_name = value [, column_name = value] | はい  | 更新対象の列を指定します。等号（=）の後ろのvalueは更新後の値です。         |
| [ WHERE condition ]                         | いいえ | WHERE句は、更新される行が満たす必要がある条件を指定します。指定しない場合、更新対象のテーブルの該当列のすべてのレコードを更新します。 |

### すべてのレコードを更新する

`t_insert` テーブルの `value` 列のすべての値を更新し、すべての値に1を加算します。例：

```sql
UPDATE t_insert SET value = value+1;
Query OK, 5 rows affected (0.007 sec)
Rows matched: 5  Changed: 5  Warnings: 0

SELECT * FROM t_insert;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10002 | 2025-12-23 11:12:23 |
|  2 | US   | 10003 | 2025-12-23 11:12:24 |
|  3 | EN   | 10004 | 2025-12-23 11:12:27 |
|  4 | JP   | 10005 | 2025-12-23 11:12:45 |
+----+------+-------+---------------------+
4 rows in set
```

`UPDATE` ステートメントを実行する際は、トランザクションが大きくなりすぎないように注意してください。`LIMIT` キーワードで更新数を制限するか、`WHERE` キーワードで更新範囲を制御できます。これは、条件を指定せずにデータを更新する場合、レコード数が数十万または数百万に達すると大規模なトランザクションが発生し、実行が失敗する可能性があるためです。

### 一部のレコードを更新する

テーブルデータを更新する際には、一部のレコードのみを更新することもできます。`t_insert` テーブルのレコード数が多い場合、`LIMIT` キーワードを追加して更新数を制限するか、`WHERE` キーワードを追加して更新範囲を制御します。

例：

* `LIMIT` を使用して、`t_insert` テーブルの最初の100,000行の `value` 列の値を `value+1` に更新します。

  ```sql
  UPDATE t_insert SET value = value+1 LIMIT 100000;
  ```

* `WHERE` を使用して、`t_insert` テーブル内で `value` の値が `10005` であるすべての行の値を `value+1` に更新します。

  ```sql
   UPDATE t_insert SET value = value+1 where value = 10005;
  ```

* `t_insert` テーブルで、`id = 3` の行の `name` 列の値を `UK` に更新します。

  ```sql
  SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   | 10003 | 2025-12-23 11:12:23 |
  |  2 | US   | 10004 | 2025-12-23 11:12:24 |
  |  3 | EN   | 10006 | 2025-12-23 11:12:27 |
  |  4 | JP   | 10006 | 2025-12-23 11:12:45 |
  +----+------+-------+---------------------+
  4 rows in set

  UPDATE t_insert SET name = 'UK' WHERE id = 3;
  Query OK, 0 rows affected

  SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   | 10003 | 2025-12-23 11:12:23 |
  |  2 | US   | 10004 | 2025-12-23 11:12:24 |
  |  3 | UK   | 10006 | 2025-12-23 11:12:27 |
  |  4 | JP   | 10006 | 2025-12-23 11:12:45 |
  +----+------+-------+---------------------+
  4 rows in set
  ```

### レコードの一意性制約違反を更新する

テーブルに一意性制約が設定されている場合、同じレコードに更新しようとすると、システムはエラーを返し、データの更新は失敗します。エラーの例は以下のとおりです。

```sql
SELECT * FROM t_insert;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10003 | 2025-12-23 11:12:23 |
|  2 | US   | 10004 | 2025-12-23 11:12:24 |
|  3 | UK   | 10006 | 2025-12-23 11:12:27 |
|  4 | JP   | 10006 | 2025-12-23 11:12:45 |
+----+------+-------+---------------------+
4 rows in set

CREATE UNIQUE INDEX uk_name ON t_insert(name);
Query OK, 0 rows affected

UPDATE t_insert SET name = 'US' where id = 3;
ERROR 1062 (23000): Duplicate entry 'US' for key 'uk_name'
```

## 他のステートメントを使用したデータの更新

明示的な `UPDATE` ステートメント以外にも、データを更新できるステートメントがあります。例えば、`INSERT` ステートメントでデータを挿入する際、制約違反が発生した場合には、`ON DUPLICATE KEY UPDATE` 句を使用して、挿入操作を関連フィールドの更新操作に変換できます。

`ON DUPLICATE KEY UPDATE` 句を使用して挿入を更新に変換する例を以下に示します：

```sql
  SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   | 10003 | 2025-12-23 11:12:23 |
  |  2 | US   | 10004 | 2025-12-23 11:12:24 |
  |  3 | UK   | 10006 | 2025-12-23 11:12:27 |
  |  4 | JP   | 10006 | 2025-12-23 11:12:45 |
  +----+------+-------+---------------------+
  4 rows in set

INSERT INTO t_insert(id, name, value) VALUES (3,'EN', 10003),(5, 'CN', 10005) ON DUPLICATE KEY UPDATE name = VALUES(name);
Query OK, 1 row affected

SELECT * FROM t_insert;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10003 | 2025-12-23 11:12:23 |
|  2 | US   | 10004 | 2025-12-23 11:12:24 |
|  3 | EN   | 10006 | 2025-12-23 11:12:27 |
|  4 | JP   | 10006 | 2025-12-23 11:12:45 |
+----+------+-------+---------------------+
4 rows in set
```

この例では、`ON DUPLICATE KEY UPDATE name = VALUES(name)` は、挿入するデータがテーブルの主キー値と重複する場合、テーブル内の競合行（元のデータ `(3,'EN', 10003)`）の `name` 列の値を、現在挿入しようとしている `name` 列の値に更新することを意味します。
