# GATHER_INDEX_STATS

`GATHER_INDEX_STATS` プロシージャは、インデックス統計情報を収集するために使用されます。

## 構文

```sql
DBMS_STATS.GATHER_INDEX_STATS (
  ownname            VARCHAR2,
  indname            VARCHAR2,
  partname           VARCHAR2 DEFAULT NULL,
  estimate_percent   NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  stattab            VARCHAR2 DEFAULT NULL,
  statown            VARCHAR2 DEFAULT NULL,
  degree             NUMBER DEFAULT NULL,
  granularity        VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  no_invalidate      BOOLEAN DEFAULT FALSE,
  force              BOOLEAN DEFAULT FALSE,
  tabname            VARCHAR2 DEFAULT NULL
);
```

## パラメータ説明

|        パラメータ       |      説明           |
|------------------|----------------------|
| ownname          | テーブルが属するスキーマ。     |
| indname          | インデックス名。   |
| partname         | パーティション名。   |
| estimate_percent | 行の推定割合。\[0.000001,100\]の範囲が有効です。 |
| stattab          | 統計情報を格納するユーザーテーブル名を指定します。 |
| statown          | 統計情報を格納するユーザーテーブルの所有者名を指定します。 |
| degree           | 並列度。デフォルト値は`NULL`です。`NULL`は`CREATE TABLE`または`ALTER TABLE`ステートメントの`DEGREE`句で指定されたテーブルのデフォルト値を使用することを意味します。`DEGREE=>NULL`や`DEGREE=>n`を使用する場合、オブジェクトのサイズが並列実行を保証しない場合、`DBMS_STATS`は直列実行を採用する可能性があります。  |
| granularity      | 収集するインデックス統計情報の粒度（テーブルがパーティション化されている場合にのみ適用されます）。 <ul><li> `ALL`：すべて（サブパーティション、パーティション、グローバル）のインデックス統計情報を収集します。</li>   <li> `APPROX_GLOBAL AND PARTITION`：`GLOBAL AND PARTITION`と類似していますが、この場合、グローバルインデックス統計情報はパーティションレベル統計情報の集計です。このオプションは、異なる値の数と異なるキーの数以外のすべてのインデックス統計情報を集計します。ただし、インデックス統計情報を持つパーティションのみを集計します。`partname`が`NULL`であるか、集計が実行できない場合（例えば、いずれかのパーティションのインデックス統計情報が欠けている場合）、グローバルインデックス統計情報を収集します。   </li>   <li> `AUTO`：パーティションタイプに基づいて粒度を決定します。これがデフォルト値です。 </li>   <li> `DEFAULT`：グローバルおよびパーティションレベルのインデックス統計情報を収集します。このオプションは廃止されており、`GLOBAL AND PARTITION`の使用を推奨します。  </li>   <li>`GLOBAL`：グローバルインデックス統計データを収集します。  </li>   <li> `GLOBAL AND PARTITION`：グローバルおよびパーティションレベルのインデックス統計情報を収集します。複合パーティションオブジェクトであっても、サブパーティションレベルのインデックス統計情報は収集されません。   </li>   <li> `PARTITION`：パーティションレベルのインデックス統計情報を収集します。   </li>   <li> `SUBPARTITION`：サブパーティションレベルのインデックス統計情報を収集します。</li>   </ul>    |
| no_invalidate| 統計情報収集時にPlan Cacheをフラッシュするかどうか。`TRUE`に設定すると、統計情報収集時にPlan Cacheをフラッシュしません。|
| force            | ロック状態を無視して強制的に収集するかどうか。デフォルトは`FALSE`です。`TRUE`に設定すると、統計情報がロックされていてもインデックス統計情報を収集します。  |
| tabname          | テーブル名。     |

## 異常時

|    エラーコード    |      説明      |
|-----------|--------------|
| HY000     |  <ul><li>該当するインデックスが存在しないか、権限が不足しています。</li><li>入力値が誤っています。</li></ul>     |

## 使用方法

このプロシージャを呼び出すには、テーブルの所有者である必要があります。

## 例

ユーザー `testUser01` の `tbl1` テーブルのインデックス `idx` の統計情報を収集します。

```sql
CALL DBMS_STATS.GATHER_INDEX_STATS('testUser01', 'idx1', degree=>4, tabname=>'tbl1');
Query OK, 0 rows affected
```

  :::info

  インデックスは現在のユーザーでは一意ではないため、seekdb ではテーブル名を明示的に指定する必要があります。

  :::
