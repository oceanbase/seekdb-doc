# LOCK_SCHEMA_STATS

`LOCK_SCHEMA_STATS` プロシージャは、スキーマ内のすべてのテーブルの統計情報をロックするために使用されます。

## 構文

```sql
DBMS_STATS.LOCK_SCHEMA_STATS(
  ownname          VARCHAR2,
  stattype         VARCHAR2 DEFAULT 'ALL');
```

## パラメータの説明

|    パラメータ    |         説明             |
|----------|---------------------------|
| ownname  | スキーマ名。   |
| stattype | ロックのタイプ。一般的に以下の3種類が含まれます： <ul><li> `'ALL'` </li>  <li> `'DATA'`   </li>  <li> `'CACHE'` </li>  </ul>    |

## 使用方法

* このプロシージャを呼び出すには、テーブルの所有者である必要があります。

* テーブルの統計情報がロックされると、そのテーブルに依存するすべての統計情報もロックされます。これには、テーブルレベルの統計情報、列レベルの統計情報、ヒストグラム統計情報、およびすべてのインデックスに依存する統計情報が含まれます。

* オブジェクトの統計情報がロックされている場合、`SET_*`、`DELETE_*`、`IMPORT_*`、`GATHER_*` プロシージャを実行して単一のテーブル、インデックス、または列の統計情報を変更しようとすると、エラーが発生します。

* `EXPORT_*_STATS` プロシージャを使用する際、ロックまたはアンロック状態はテーブルレベルの統計情報と共にエクスポートされません。

* `UNLOCK_SCHEMA_STATS` プロシージャおよび `UNLOCK_TABLE_STATS` プロシージャでは、対応するパーティションの統計情報をアンロックすることはできません。`LOCK_TABLE_STATS` プロシージャを呼び出すと、テーブルレベルでロック位置が設定されるため、その時点ではパーティションやインデックスなどの依存オブジェクトに関する統計情報を収集することはできません。また、テーブルレベルの統計情報がロックされている場合、その依存関係もロックされるため、パーティションの統計情報をロックするために `LOCK_PARTITION_STATS` プロシージャを明示的に呼び出す必要はありません。

## 例

`hr` スキーマ下のすべてのテーブルの統計情報をロックします。

```sql
CALL DBMS_STATS.LOCK_SCHEMA_STATS(ownname=>'hr', stattype=>'ALL');
Query OK, 0 rows affected
```
