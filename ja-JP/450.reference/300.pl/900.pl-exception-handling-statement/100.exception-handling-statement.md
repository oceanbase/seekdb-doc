# 例外処理の概要

ストアドプログラムの実行中には、現在のプログラムブロックを終了するなど、特別な状況が発生し、それを処理する必要が生じることがあります。ユーザーは、警告や例外などの状況に対してハンドラーを定義したり、エラーコードを指定したりできます。

SEEKDBは、以下のPL例外処理文をサポートしています：

* `DECLARE ... CONDITION` 文は、例外条件に名前を付けるために使用されます。詳細については、[DECLARE ... CONDITION](../900.pl-exception-handling-statement/200.declare-condition.md)を参照してください。

* `DECLARE ... HANDLER` 文は、ハンドラーを宣言するために使用されます。詳細については、[DECLARE ... HANDLER](../900.pl-exception-handling-statement/300.declare-handler.md)を参照してください。

* `RESIGNAL` 文は、例外処理ハンドラー内の例外情報を変更するために使用されます。詳細については、[RESIGNAL](../900.pl-exception-handling-statement/500.resignal.md)を参照してください。

* `SIGNAL` 文は、例外条件を発生させるために使用されます。詳細については、[SIGNAL](../900.pl-exception-handling-statement/600.signal.md)を参照してください。

* `GET DIAGNOSTICS` 文は、診断領域から情報を取得するために使用されます。詳細については、[GET DIAGNOSTICS](../900.pl-exception-handling-statement/400.get-diagnostics.md)を参照してください。

例外状況が発生した場合、サーバーがどのようにしてハンドラーを選択するかに関する情報については、[ハンドラーの有効範囲](../900.pl-exception-handling-statement/700.scope-rules-for-handlers.md)を参照してください。

診断領域に関する情報については、[診断領域](../900.pl-exception-handling-statement/800.diagnostic-area.md)を参照してください。
