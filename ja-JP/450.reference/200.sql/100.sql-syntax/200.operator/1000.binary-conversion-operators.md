# BINARY変換演算子

seekdbは`BINARY`強制型変換演算子をサポートしています。

## BINARY演算子の構文

`BINARY`演算子の構文は次のとおりです：

```sql
BINARY expr
```

`BINARY`演算子は、`expr`式をバイナリ文字列（バイナリ文字セットとバイナリソート規則を持つ文字列）に変換します。
文字列比較では、`BINARY`は通常、文字ごとの比較ではなく、文字列のバイナリ値を比較するために使用され、比較時には末尾のスペースが考慮されます。例：

```sql
SELECT 'aa' = 'AA';
+-------------+
| 'aa' = 'AA' |
+-------------+
|           1 |
+-------------+
1 row in set (0.001 sec)

SELECT BINARY 'aa' = 'AA';
+--------------------+
| BINARY 'aa' = 'AA' |
+--------------------+
|                  0 |
+--------------------+
1 row in set (0.001 sec)

SELECT 'aa' = 'aa ';
+--------------+
| 'aa' = 'aa ' |
+--------------+
|            1 |
+--------------+
1 row in set (0.000 sec)

SELECT BINARY 'aa' = 'aa ';
+---------------------+
| BINARY 'aa' = 'aa ' |
+---------------------+
|                   0 |
+---------------------+
1 row in set (0.000 sec)
```

## バイナリ文字列変換の説明

seekdbでは、文字列式をバイナリ文字列に変換するには、以下の3つの方法を使用できます：

```sql
CONVERT(expr USING BINARY)
CAST(expr AS BINARY)
BINARY expr
```

注意点として、式内の`BINARY`演算子と、文字列定義における`BINARY`データ型は、異なる効果を持ちます。`BINARY`属性で定義された列に対しては、データベースはテーブルのデフォルト文字セットとその文字セットのバイナリ(_bin)ソート規則を割り当てます。すべての非バイナリ文字セットにはBinソート規則が存在します。例えば、テーブルのデフォルト文字セットがGBKの場合、以下の2つの列定義は等価です：

```sql
CHAR(5) BINARY
<=>
CHAR(5) CHARACTER SET gbk COLLATE gbk_bin
```

`CHAR`、`VARCHAR`、または`TEXT`列の定義で`CHARACTER SET binary`を使用すると、その列は対応するバイナリ文字列データ型と見なされます。以下の例の定義は等価です：

```sql
CHAR(5) CHARACTER SET binary
<=>
BINARY(5)

VARCHAR(10) CHARACTER SET binary
<=>
VARBINARY(10)

TEXT CHARACTER SET binary
<=>
BLOB
```
