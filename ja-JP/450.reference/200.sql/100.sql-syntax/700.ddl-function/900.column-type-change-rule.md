# 列型変更ルール

SEEKDBで列型を変更する際には、まずテーブルレベルの列型変更ルール、特に一部のデータ型の禁止シナリオを考慮する必要があります。次に、列型変更におけるソースデータ型とターゲットデータ型の変更ルールを検討します。

## テーブル単位の列型変更ルール

### 禁止ルール

* 外部キー制約

  Online DDLとOffline DDLにおいて、以下の特別な場合を除き（注意：該当する型の変更は表示精度のみを変更し、格納構造は変更しない）、外部キー列の型を変更することはサポートされません。

  * 列のデータ型が `FLOAT(m,n)` の場合、精度の変更はサポートされますが、`SIGNED` と `UNSIGNED` の相互変換はサポートされません。

  * 列のデータ型が `DOUBLE(m,n)` の場合、精度の変更はサポートされますが、`SIGNED` と `UNSIGNED` の相互変換はサポートされません。

  * 列のデータ型が `VARCHAR(m)` の場合、精度を上げる変更はサポートされますが、精度を下げる変更や `CHAR` 型への変更はサポートされません。

* `CHECK` 制約

  Online DDLとOffline DDLにおいて、整数型（`INTEGER`）の列を除き、`CHECK` 制約を持つ列の型を変更することはサポートされません。

* Trigger制約

  Offline DDLにのみ適用されます。列に `DISABLE` 以外のTrigger制約がある場合、列の型を変更することは禁止されます。すべてのTriggerが `DISABLE` である場合、DDL操作には影響せず、新しいテーブルにもこの `DISABLE` のTriggerを含める必要があります。

### 変更ルール

* 同一データ型で長さが長くなる場合、例えばある列のデータ型を `VARCHAR(8)` から `VARCHAR(11)` に変更する操作は、Online DDLとして実行でき、データの再書き込みは不要です。

  * Online DDLで列の長さを変更する際、その列にインデックステーブルが存在する場合（例えば `VARCHAR` 型の長さが長くなる場合）、Online DDLで変更すると同時に、インデックステーブルなどの依存オブジェクトのスキーマも変更する必要があります。つまり、**「ユーザーが想定するデータの変更はないが、依存オブジェクトのスキーマも変更する必要がある」ということです**。
  * `INTEGER` および `DecimalInt` 型の列について、それらがインデックス列または主キー列である場合、列型を長くする操作はOnline DDLで実行できます。

* seekdbにおいて、`LOB` 型の長さを増やす場合、Online DDL操作は以下の状況をサポートします：

  * 通常の列の変更。
  * 生成列（Store/Virtual）としての変更
  * 生成列に依存する（Store/Virtual）変更
  * `NOT NULL` および `CHECK` 制約の追加。
  * 既存の `NOT NULL` 制約の変更。

* 数値データ型において、`SIGNED` と `UNSIGNED` の変換が発生した場合、型変更が許可される場合は、Offline操作を実行する必要があります。文字データ型において、文字セットや照合順序（Collation）の変更が発生した場合、列型の変更が許可される場合は、Offline操作を実行する必要があります。

* ある列が生成列によって参照されている場合、列型の変更操作は許可されます。

## 列レベルの変換ルール

seekdbでは、すべての列データ型は数値データ型、文字データ型、時間データ型の3つの大きなカテゴリに分類されます。これら3つの大カテゴリ内での変換ルールは類似しており、各大カテゴリ間での変更ルールも類似していますが、いくつかの特殊なケースもあります。

以下の各表は、それぞれの大カテゴリ内および大カテゴリ間の変換状況を列挙したものです。

| MEDIUMINT | サポートなし      | N/A          | サポート    | サポート       |

| データ型  | To USMALLINT | To UMEDIUMINT | To UINT | To UBIGINT |
|------------|--------------|---------------|---------|------------|

| UINT       | ノンサポート     | ノンサポート     | N/A    | サポート      |

### DECIMAL/DECIMALINT

`DECIMAL(precision, scala)` は10進数型を表し、`precision` は数値の全長、`scala` は小数部の桁数を表します。`precision` のOnline DDL時の精度範囲は [1, 9]、[10, 18]、[19, 38]、[39, 65] です。

:::tip

seekdbでは `precision` の最大値は65です。

:::

`precision` の長さが同一範囲内で `scala` が変わらない場合、基盤となる物理ストレージは変更されず、Online DDLによる変更が可能です。例えば、`DECIMAL(10, 2)` から `DECIMAL(12, 2)` への変更は、Online DDLを使用して行うことができます。

* 最初のパラメータ `precision` の変更について、長くする場合（つまり `precision` の長さを増やす場合）は、Online DDLを使用して変更できます。例えば、`DECIMAL(10, 2)` から `DECIMAL(12, 2)` への変更は、Online DDLを使用して行うことができます。しかし、短くする場合（つまり `precision` の長さを減らす場合）は、Online DDLでは変更できず、Offline DDLを使用して変更する必要があります。区間をまたぐ場合もOffline DDLを使用して変更する必要があります。

* 2番目のパラメータ `scala` の変更について、長くする場合も短くする場合も、Online DDLでは変更できず、Offline DDLを使用して変更する必要があります。例えば、`DECIMAL(10, 2)` から `DECIMAL(10, 4)` への変更、または `DECIMAL(10, 2)` から `DECIMAL(10, 1)` への変更は、Offline DDLを使用して行う必要があります。

### VARCHARの可変長化

`VARCHAR(x)` を `VARCHAR(y)` に変換する場合、`y` の長さが `x` の長さ以上であれば、Online DDLを使用して列型を上げる変更を行うことができます。例えば、`VARCHAR(10)` を `VARCHAR(20)` に変換する場合、Online DDLを使用して列型を変更することができます。

### VARBINARYの可変長化

`VARBINARY(x)` を `VARBINARY(y)` に変換する場合、`y` の長さが `x` の長さ以上であれば、Online DDLを使用して列型を上げる変更を行うことができます。例えば、`VARBINARY(10)` を `VARBINARY(20)` に変換する場合、Online DDLを使用して列型を変更することができます。
