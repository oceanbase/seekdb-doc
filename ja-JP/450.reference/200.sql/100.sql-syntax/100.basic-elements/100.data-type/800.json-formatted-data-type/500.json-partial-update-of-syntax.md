# JSONデータの部分更新

seekdbはJSONデータの部分更新（Json Partial Update）をサポートしています。JSONドキュメント内の特定のフィールドのみを変更する場合、この機能により、JSONドキュメント全体を完全に更新することなく、変更したい部分のみを更新できます。

## 使用上の制限

## Json Partial Updateスイッチ

seekdbのJson Partial Update機能はデフォルトで無効です。このスイッチはシステム変数`log_row_value_options`によって制御されます。詳細については、[log_row_value_options](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001972193)を参照してください。

**例：**

* Json Partial Update機能を有効にします。

  * セッションレベル：

  ```sql
  SET log_row_value_options="partial_json";
  ```

  * グローバルレベル：

  ```sql
  SET GLOBAL log_row_value_options="partial_json";
  ```

* Json Partial Update機能を無効にします。

  * セッションレベル：

  ```sql
  SET log_row_value_options="";
  ```

  * グローバルレベル：

  ```sql
  SET GLOBAL log_row_value_options="";
  ```

* `log_row_value_options`の値を照会します。

  ```sql
  SHOW VARIABLES LIKE 'log_row_value_options';
  ```

  実行結果は次のとおりです：

  ```sql
  +-----------------------+-------+
  | Variable_name         | Value |
  +-----------------------+-------+
  | log_row_value_options |       |
  +-----------------------+-------+
  1 row in set
  ```

## Partial Updateで使用可能なJSON式

JSON Partial Update機能のスイッチ `log_row_value_options` に加えて、JSONドキュメントを更新するための特定の式を使用する必要があります。これにより、JSON Partial Updateがトリガーされます。

現在、seekdbでPartial Updateが可能なJSON式は以下のとおりです：

* json_setまたはjson_replace：JSONフィールドの値を更新するために使用します。
* json_remove：JSONフィールドを削除するために使用します。

:::tip

1. `SET`代入句の左辺の操作数とJSON式の最初のパラメータが同じであること、かつ両方ともテーブル内のJSON列であることを確認する必要があります。例えば、`j = json_replace(j, '$.name', 'ab')` の場合、等号の左側のパラメータと等号の右側のJSON式 `json_replace` の最初のパラメータはどちらも `j` です。
2. 現在のJSON列のデータが `outrow` ストレージである場合にのみ、JSON Partial Updateがトリガーされます。`outrow` または `inrow` ストレージは、テーブル作成時のパラメータ `lob_inrow_threshold` によって制御されます。`lob_inrow_threshold` は `INROW` 閾値を設定するために使用され、LOBデータサイズがこの閾値を超えると、LOB Metaテーブル内で `OUTROW` ストレージに変換されます。デフォルトは4KBです。

:::

**例：**

1. テーブル `json_test` を作成します。

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON);
   ```

2. データを挿入します。

   ```sql
   INSERT INTO json_test VALUES(1, CONCAT('{"name": "John", "content": "', repeat('x',8), '"}'));
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.002 sec)
   ```

3. JSON列 `j` のデータをクエリします。

   ```sql
   SELECT j FROM json_test;
   ```

   実行結果は次のとおりです：

   ```shell
   +-----------------------------------------+
   | j                                       |
   +-----------------------------------------+
   | {"name": "John", "content": "xxxxxxxx"} |
   +-----------------------------------------+
   1 row in set (0.003 sec)
   ```

4. `json_repalce` を使用して、JSON列 `name` フィールドの値を更新します。

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.name', 'ab') WHERE pk = 1;
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.003 sec)
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

5. JSON列 `j` の変更後のデータをクエリします。

   ```sql
   SELECT j FROM json_test;
   ```

   実行結果は次のとおりです：

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "ab", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set (0.000 sec)
   ```

6. `json_set` を使用して、JSON列 `name` フィールドの値を更新します。

   ```sql
   UPDATE json_test SET j = json_set(j, '$.name', 'cd') WHERE pk = 1;
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.003 sec)
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

7. JSON列 `j` の変更後のデータをクエリします。

   ```sql
   SELECT j FROM json_test;
   ```

   実行結果は次のとおりです：

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "cd", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set (0.000 sec)
   ```

8. `json_remove` を使用して、JSON列 `name` フィールドの値を削除します。

   ```sql
   UPDATE json_test SET j = json_remove(j, '$.name') WHERE pk = 1;
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.003 sec)
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

9. JSON列 `j` の変更後のデータをクエリします。

   ```sql
   SELECT j FROM json_test;
   ```

   実行結果は次のとおりです：

   ```shell
   +-------------------------+
   | j                       |
   +-------------------------+
   | {"content": "xxxxxxxx"} |
   +-------------------------+
   1 row in set (0.000 sec)
   ```

## 更新の粒度

seekdbのJSONデータはLob形式で保存されており、seekdbのLobは基盤としてブロック単位で格納されます。そのため、Partial Updateを行う際のデータ量は、少なくとも1つのLobブロック単位となります。Lobブロックが小さければ小さいほど、書き込むデータ量は少なくなります。このため、列作成時にLobブロックサイズを指定するDDL構文も提供されています。

**例：**

```sql
CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '4k');
```

Chunk Sizeは無限に小さくすることはできません。小さすぎると`SELECT`、`INSERT`、`DELETE`のパフォーマンスに影響します。一般的には、JSONドキュメントの平均フィールドサイズに基づいて設定することを推奨します。大部分のフィールドが小さい場合は、1Kに設定できます。seekdbはLob型の読み取りを最適化するため、4K未満のデータについては直接`INROW`で保存し、この場合はPartial Updateは行われません。Partial Updateは主に大規模なドキュメントの更新パフォーマンスを向上させるためのものであり、小規模なドキュメントでは全量更新の方がパフォーマンスが良い場合があります。

## Rebuild

Json Partial Updateは、Json列の更新前後のデータ長に制限を設けません。新しい値の長さが古い値の長さ以下の場合、元の場所のデータを新しいデータで直接置き換えます。新しい値の長さが古い値の長さを超える場合、最後に新しいデータをAppendします。seekdbはしきい値を設定しており、Appendされるデータの長さが元のデータ長の30％を超えるとRebuildが実行されます。この場合、Partial Updateは行われず、データは完全に上書きされます。

`JSON_STORAGE_SIZE` 式を使用してJSONの実際のストレージ長を取得し、`JSON_STORAGE_FREE` を使用して追加のストレージオーバーヘッドを取得できます。

**例：**

1. Json Partial Updateを有効にします。

   ```sql
   SET log_row_value_options = "partial_json";
   ```

2. テストテーブル `json_test` を作成します。

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '1K');
   ```

3. テーブル `json_test` に1行のデータを挿入します。

   ```sql
   INSERT INTO json_test VALUES(10 , json_object('name', 'zero', 'age', 100, 'position', 'software engineer', 'profile', repeat('x', 4096), 'like', json_array('a', 'b', 'c'), 'tags', json_array('sql boy', 'football', 'summer', 1), 'money' , json_object('RMB', 10000, 'Dollers', 20000, 'BTC', 100), 'nickname', 'noone'));
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.003 sec)
   ```

4. `JSON_STORAGE_SIZE` を使用してJson列のストレージサイズ（実際に使用されているストレージ容量）を確認し、`JSON_STORAGE_FREE` を使用してJson列から解放できるストレージ容量を見積もります。

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   実行結果は次のとおりです：

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    0 |
   +----------------------+----------------------+
   1 row in set
   ```

   Partial Updateが行われていないため、`JSON_STORAGE_SIZE` の値は4335、`JSON_STORAGE_FREE` の値は0です。

5. `json_replace` を使用してJson列 `position` フィールドの値を更新します。新しい値の長さは古い値の長さより短いです。

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software enginee') WHERE pk = 10;
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 1 row affected (0.003 sec)
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

6. 再度 `JSON_STORAGE_SIZE` を使用してJson列のストレージサイズを確認し、`JSON_STORAGE_FREE` を使用してJson列から解放できるストレージ容量を見積もります。

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   実行結果は次のとおりです：

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4334 |                    0 |
   +----------------------+----------------------+
   1 row in set (0.000 sec)
   ```

   Json列のデータを更新した後、新しいデータが古いデータより1バイト少ないため、`JSON_STORAGE_SIZE` の値は4334、`JSON_STORAGE_FREE` の値は依然として0です。

7. `json_replace` を使用してJson列 `position` フィールドの値を更新します。新しい値の長さは古い値の長さより長いです。

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software engineera') WHERE pk = 10;
   ```

   実行結果は次のとおりです：

   ```shell
   Query OK, 0 rows affected (0.001 sec)
   Rows matched: 1  Changed: 0  Warnings: 0
   ```

8. 再度 `JSON_STORAGE_SIZE` を使用してJson列のストレージサイズを確認し、`JSON_STORAGE_FREE` を使用してJson列から解放できるストレージ容量を見積もります。

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   実行結果は次のとおりです：

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4355 |                   19 |
   +----------------------+----------------------+
   1 row in set (0.001 sec)
   ```

   Json列のデータをAppend更新した後、`JSON_STORAGE_FREE` の長さは19であり、Rebuild後に19バイトを解放できることを意味します。
