# JSON_SCHEMA_VALID

## 説明

この関数は、JSONドキュメントを検証します。JSONドキュメントがJSON Schema仕様に準拠している場合は1を返し、準拠していない場合は0を返します。列制約に利用できます。

## 構文

```sql
JSON_SCHEMA_VALID(schema, document)
```

## 説明

* パラメータ `schema` はJSON Schemaを指定するために使用され、Schemaは有効なJSONオブジェクトでなければなりません。

  * JSON Schemaでは、`required` 属性を使用して必須のプロパティを強制することができます。

  * JSON Schemaでは `id`、`$schema`、`description`、`type` 属性をサポートしていますが、これらの属性の提供は必須ではありません。

* パラメータ `document` は検証対象のJSONドキュメントを指定するために使用され、このJSONドキュメントは有効なJSONドキュメントでなければなりません。

* いずれかのパラメータが有効なJSONでない場合、この関数はエラーを発生させます。

## 例

以下の例では、`'{"type": "string"}'` を使ってJSON Schemaを定義しており、このSchemaは有効なJSONデータが文字列型である必要があることを示しています。`'"JSON_doc"'` は検証対象のJSONドキュメントです。

:::tip

このステートメントでは、文字列 `JSON_doc` が二重引用符（"）で囲まれており、それが通常の文字列ではなく有効なJSON文字列であることを示しています。JSONでは、文字列値は二重引用符で囲む必要があります。

:::

```sql
SELECT JSON_SCHEMA_VALID('{"type": "string"}', '"JSON_doc"');
```

戻り値は次のとおりです：

```shell
+-------------------------------------------------------+
| JSON_SCHEMA_VALID('{"type": "string"}', '"JSON_doc"') |
+-------------------------------------------------------+
|                                                     1 |
+-------------------------------------------------------+
1 row in set (0.001 sec)
```

この例では、JSONドキュメントが有効なJSON文字列であり、Schemaで定義された文字列型に準拠しているため、関数は検証に合格したことを示す `1` を返します。
