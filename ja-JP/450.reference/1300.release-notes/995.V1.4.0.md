# V1.4.0

## バージョン情報
+ リリース日: 2026年8月27日
+ バージョン: V1.4.0
+ RPM バージョン: seekdb-1.4.0-100000172026082615

## バージョン概要
seekdb V1.4.0では、システムの軽量化を進めました。全体的な最適化とリファクタリングを行い、リソース消費を大きく抑えています。組み込みアクセスアーキテクチャを見直し、複数のアプリケーションで同じインスタンスを共有できるようにしました。macOSでの安定性も改善しています。RustスタックとBazelビルドサポート（プレビュー版）を新たに追加し、開発者にとって扱いやすい環境づくりも進めました。

## 主な改善点
### リソースオーバーヘッドの大幅削減
V1.4.0 ではエンジンを軽量化し、組み込み環境、エッジ環境、低スペック環境でのリソース消費を大幅に削減しました。

**バイナリおよびパッケージサイズ**

| 項目 | V1.3.0 | V1.4.0 | 削減率 |
| --- | --- | --- | --- |
| バイナリ | 366.2 MiB | 132.4 MiB | 63.9% |
| Python パッケージ | 160.0 MiB | 50.0 MiB | 68.8% |


**定常状態のランタイムリソース**

| 項目 | V1.3.0 | V1.4.0 | 削減率 |
| --- | --- | --- | --- |
| 定常状態 CPU（平均） | 0.05 コア | 0.01 コア | 70.3% |
| 定常状態メモリ（平均） | 630.6 MiB | 166.3 MiB | 73.6% |


**ビルド時間（macOS / M4）**

| 項目 | V1.3.0 | V1.4.0 | 削減率 |
| --- | --- | --- | --- |
| 経過ビルド時間 | 16:31.7 | 6:16.4 | 62.0% |
| ビルド CPU 時間 | 7080.5s | 2482.9s | 64.9% |


主な最適化項目:

+ **アロケータ最適化**: jemalloc を導入し、メモリフラグメンテーションを削減しました。
+ **アイドル時の常駐メモリ削減**: memstore、plan cache、KV cache などでアイドル時のメモリ回収を行うようにし、常駐メモリ使用量を大幅に削減しました。
+ **スレッドおよびスタックオーバーヘッド削減**: 不要なバックグラウンドスレッドを削減し、デフォルトのスレッドスタックサイズを引き下げました。
+ **コードサイズ削減**: 不要なコードと依存関係を見直し、コードセグメントを縮小しました。

### macOS の安定性向上
seekdb V1.4.0 では、macOS 上でのランタイム品質を全体的に改善しました。GIS 計算、ソート、数値型変換、浮動小数点演算、PLにおけるmacOS固有の挙動差異を修正したほか、ログタイムスタンプのフォーマット性能も改善しています。

## 新機能
### 組み込みアクセスアーキテクチャのアップグレード
V1.4.0 では、組み込みモードの実行方式を、ホストプロセス内でのインプロセス実行から、MySQL プロトコルで通信する独立したバックグラウンドプロセス方式へ変更しました。

+ **複数言語からの統一アクセス**: 各言語バインディングが独自のカーネルアーティファクトをビルドする必要がなくなりました。アクセスは、[seekdb-bindings](https://github.com/oceanbase/seekdb-bindings) が提供する共通基盤を通じて統一されます。
+ **複数アプリケーションによる同一インスタンスの共有**: 複数の組み込みアプリケーションが同じデータベースインスタンスに同時にアクセスできるようになり、アプリケーション間でのデータ共有が可能になりました。

## 機能強化
### PL 実行フレームワークのリファクタリング
V1.4.0では、PL 実行フレームワークを LLVM JIT ベースの Just-In-Time コンパイル方式からツリーウォーキングインタプリタ方式へ刷新しました。これにより、ビルド時の依存関係やランタイムオーバーヘッドを抑えながら、クロスプラットフォームでの一貫性を高めています。多くのシナリオで実用的な実行性能を維持しつつ、軽量化とのバランスを図りました。

## 開発者エコシステム
### Rust スタックの導入
V1.4.0 では、seekdb の開発スタックに Rust を初めて導入しました。MySQL プロトコルスタックとネットワーク I/O レイヤーはすべて Rust で書き直され、seekdb は純 C++ スタックから C++ と Rust のハイブリッドスタックへ移行しました。Rust のメモリ安全性と型システムは、低レベルモジュールを長期的に進化させていくための、より堅牢な基盤となります。また、Rust に詳しい開発者が、大規模な純 C++ プロジェクトに慣れるための負担を抑えながら、コアモジュールに直接貢献できるようになります。

### Bazel ビルドサポート（Preview）
V1.4.0 では、開発者およびコミュニティコントリビューター向けに、ネイティブ Bazel モジュール（Bzlmod）をプレビュー版のビルドシステムオプションとして導入しました。Bazel はインクリメンタルコンパイルやビルド結果のキャッシュに対応しているほか、大規模な C++ プロジェクトにおける依存関係の境界管理や可視化にも適しています。これにより、モジュール間の結合に起因するビルドおよび保守コストの削減を図っています。本機能は現在プレビュー段階にあり、今後もビルド基盤と依存関係管理を改善していく長期的な取り組みの一環として、継続的に強化していく予定です。

## バグ修正
### ベクトルインデックスの修正
+ SINDI スナップショットのデシリアライズ失敗を修正しました（[d08a76bc](https://github.com/oceanbase/seekdb/commit/d08a76bc)）
+ HGRAPH スナップショットのキープレフィックスに関する問題を修正しました（[1e6936f8](https://github.com/oceanbase/seekdb/commit/1e6936f8)）
+ ベクトルインデックスの schema manager GC と VSAG パラメータ検証に関する問題を修正しました（[4d1da7fb](https://github.com/oceanbase/seekdb/commit/4d1da7fb)）
+ フィルタ列に prefix-length index がある場合に、vector APPROXIMATE search がエラー -4016 を返す問題を修正しました（[23c3a554](https://github.com/oceanbase/seekdb/commit/23c3a554)）
+ semantic index が生成列で semantic_distance を誤って使用する問題を修正しました（[6e53dd10](https://github.com/oceanbase/seekdb/commit/6e53dd10)）
+ 組み込みモードでインデックスのリフレッシュがタイムアウトする問題を修正しました（[ae46c8b6](https://github.com/oceanbase/seekdb/commit/ae46c8b6)）
+ ベクトルインデックス作成時にエラー 5703 が発生する問題を修正しました
+ Change Stream において、主キーが負数の場合の slice index の正規化に関する問題を修正しました。



### SQL および実行に関する修正
+ CAS シナリオにおける plan cache の集計エラーを修正しました（[8b956047](https://github.com/oceanbase/seekdb/commit/8b956047)）

+ Windows 上での PL handler compatibility に関する問題を修正しました（[fb611ec2](https://github.com/oceanbase/seekdb/commit/fb611ec2)）

### トランザクション関連の修正

## アップグレードに関する注意事項
+ V1.0.x、V1.1.0、V1.2.0、V1.3.0 から V1.4.0 へのインプレースアップグレードはサポートされていません。アップグレードする場合は、OBDUMPER/OBLOADER または mysqldump を使用して論理移行を行ってください。

詳細な手順については、[Upgrading seekdb via mysqldump](https://docs.seekdb.ai/seekdb/ja/upgrading-via-mysqldump/) を参照してください。
