## 新機能

### MACコンパイルのサポート

V1.1.0バージョンから、seekdbはMacOS 15以降のシステムでネイティブコンパイルおよびローカル開発デバッグをサポートしています。

Macにseekdbをインストールする詳細については、[パッケージ管理ツールによるseekdbのデプロイ](../../400.guides/400.deploy/700.server-mode/100.deploy-by-systemd.md)を参照してください。

### Fork Table（実験的機能）

seekdb V1.1.0バージョンでは、Fork Table機能が追加されました。従来のCTASの全量データコピーとは異なり、Fork Tableはデータ量に関係なく高速な複製方法を提供します。テーブルレベルのストレージ再利用とコピーオンライトの技術に基づき、一貫性のあるセマンティクスを満たす前提で、既存のデータ組織とストレージ構造を可能な限り再利用し、全量コピーを回避することで、作成時間とリソース消費を大幅に削減します。

Fork Tableの詳細については、[Fork Table](https://www.oceanbase.ai/docs/fork-table-overview)を参照してください。

:::tip
V1.1.0バージョンでは、Fork Tableは実験的機能です。本番環境での使用は慎重に行ってください。今後のバージョンで正式な本番機能へと継続的に改善されます。
:::

**代表的なユースケース**：

* AI Codingのセキュリティテスト：AIコードアシスタントは、テーブル構造とサンプルデータに基づいてSQL、ORMコード、データインターフェースを生成するため、データテーブル構造やデータを変更する必要が生じる場合があります。Fork Tableを使用してAI Codingに「安全なテストデータ環境」を提供することで、AIは実際のデータ構造とデータ分布に近い状態で学習・試行が可能となり、問題がないことを確認したうえで変更を本番環境に適用できます。

* AIナレッジベースのマルチバージョン管理：オンラインナレッジベースがユーザーにサービスを提供している一方で、バックエンドでは多数のFAQ/ドキュメントエントリを更新する必要が生じるシナリオがあります。新しい知識の品質が完全に検証されていないため、直接オンラインに適用することはできません。このような場合、複数のバージョンの知識を保持する必要があります。Fork Tableを使用すると、オンラインナレッジベースを迅速に複製でき、バックエンドでの新しいテーブルに基づく変更がオンラインサービスに影響を与えることはありません。新しい知識の検証が完了したら、rename tableを実行して新しいバージョンをオンラインバージョンとして推進します。

* ナレッジの共有とプライベート管理：複数の顧客/ビジネスラインにAIナレッジベースを提供する必要がある場合、共有されるべき基本知識が存在する一方で、顧客/ビジネスによっては部分的に差異化された内容も存在する可能性があります。このシナリオでは、Fork Tableを使用して「共通知識のメインテーブル」から複数の新しいテーブルをforkし、各forkテーブルに個別のプライベートドキュメントを追加したり、カスタマイズしたりして、権限とリリースのペースを個別に制御できます。

* A/B TEST：同一の本番データから複数の実験バージョンを迅速に作成し、異なるインデックス/パラメータ/SQLの書き方の効果を比較することで、全量コピーによる時間とコストのオーバーヘッドを回避します。

* データテーブル変更の事前検証(Offline DDL)：フィールド型の変更やテーブル構造の調整など、高リスクな操作を行う際に、まずはForkしてコピーを作成し、事前の演習と検証を行うことで、元のテーブルに直接操作することによる予期しない業務への影響を回避します。

* CI/CD検証：CI/CDプロセスにFork Tableのステップを追加することで、コード変更を本番環境にリリースする前に、本番データのスナップショットに基づいて、よりリアルなシナリオに近い検証を行うことができます。同時に、本番データと業務に影響を与えません。

**構文**：`FORK TABLE source_table TO destination_table;`

**効果**：`source_table` のデータスナップショットに基づいて、`destination_table` の新しいテーブルを作成します。両方のテーブルは独立したテーブルオブジェクトとして読み書きが可能で、互いに干渉しません。また、drop/rename tableを使用してデータバージョンのロールバックやバージョンの推進を実現できます。

**パフォーマンス**：Forkの所要時間はわずか数百ミリ秒です。

### ストレージ容量の最適化

seekdb V1.1.0では、データストレージ、Clogストレージ、システムログストレージに関して、最小リソース構成を全面的に最適化し、開発者のハードルをさらに引き下げました。具体的な内容は以下の通りです：

* データディスクの割り当て戦略の最適化：seekdb起動時にデータディスク容量を事前割り当てしますが、軽負荷環境では実際には数十MBしか使用されません。設定が高すぎるとディスクの無駄遣いにつながります。そのため、seekdb V1.1.0ではデータディスクのデフォルトサイズを2GBから32MBに調整しました。同時に、自動拡張のデフォルトステップサイズも2GBから、システムの自己適応拡張ステップサイズをデフォルトで使用するよう調整しました。つまり、datafile < 1GBの場合は、現在のdatafileを拡張ステップサイズとして倍増させ、データディスクサイズが1GBに達した後は、1GBをステップサイズとして拡張します。必要に応じて、`datafile_size/datafile_next`パラメーターで戦略を調整することも可能です。

* CLOGディスク使用量の最適化：従来のseekdbでは、CLOGディスクのデフォルト設定は10GBでした（一部のデプロイツールやコンテナイメージではデフォルトで2GBに調整されていました）。インスタンス起動時に対応するログ空間を事前割り当てするため、小規模環境にはあまり適していませんでした。新バージョンでは、ログ空間の割り当てと回収戦略を最適化し、デフォルトのCLOGディスクサイズをmemory_limitの1/2に調整し、下限を2GBとしました。同時に、チェックポイントSCNを定期的に進め、古いログを可能な限り回収し、CLOGディスクの水位を低い水準に保ちます。大規模環境では、より多くのCLOGログを保持する必要がある場合、`log_disk_size/log_disk_utilization_threshold`パラメーターを調整することで実現できます。

* システムログのデフォルトディスク使用量の最適化：seekdb V1.1.0では、デフォルトのシステムログレベルをWDIAGからWARNに調整し、デフォルトで保持するログ数を4個から2個に変更しました。これにより、ログ出力量を削減し、ストレージコストを低減し、システム性能を向上させます。seekdbは7種類のログレベルをサポートしており、出力頻度の高い順に次のとおりです：`DEBUG → TRACE → WDIAG → EDIAG → INFO → WARN → ERROR`。DEBUG、TRACE、WDIAG、EDIAGは診断用ログで、粒度が細かく、主に開発とデバッグのシナリオで使用され、テストや問題のトラブルシューティングに適しています。INFO、WARN、ERRORはDBAおよび運用保守担当者向けで、システム状態の監視、異常の通知、重要なエラーの記録に使用され、より高い実用性と可読性を備えています。不要なログ出力がパフォーマンスとストレージに影響を与えるのを避けるため、今回のリリースではデフォルトのログレベルをWARNに調整しました。ユーザーは実際のニーズに応じて、`syslog_level`パラメーターでシステムログレベルを変更することができ、`max_syslog_file_count`パラメーターで保持するログの最大数を調整することもできます。

### メモリ管理の最適化

seekdb V1.1.0では、メモリ管理戦略を最適化し、異なるデプロイ環境（例：大/小メモリ構成、独立/非独立デプロイ）の要件に適応させました。具体的な最適化は以下の通りです：

* 動的メモリ使用戦略：`memory_limit`パラメーターでseekdbのメモリ使用上限を制御します。通常の実行時には、プロセスはこの制限を超えないようにします。しかし、ダンプマージ、データインポート、ソートなど一時的にメモリ消費が高いシナリオでは、システムに利用可能なメモリがある場合、短時間の上限超過を許可し、小規模環境でのシステム安定性と処理能力を向上させます。大量データや高性能が求められるシナリオでは、実際のニーズに応じてこの値を引き上げることを推奨します。

* 新規設定可能なメモリのハードリミットメカニズム：`memory_hard_limit`パラメーターを導入し、seekdbが使用できる最大メモリ総量を設定します。デフォルト値は0で、システムメモリ総量の90%をハード上限とし、必要に応じて調整をサポートします。このメカニズムにより、動的メモリ申請によるリソースの過剰占有を防ぐことができ、特に非独立デプロイ環境に適しており、共存するコンポーネントへの影響を効果的に回避できます。

## 構成パラメータの変更

| **パラメータ名** | **変更タイプ** | **変更の説明** |
| --- | --- | --- |
| _advance_checkpoint_interval | 新規 | CLOGによるチェックポイントの定期的な進める頻度を制御します。デフォルトは10mで、10分ごとに進めることを意味します。0に設定するとこの機能を無効にします。 |
| memory_hard_limit | 新規 | seekdbの最大利用可能メモリを制御します。デフォルト値は0で、システムメモリの90%をメモリのハードリミットとして使用します。 |
| syslog_level | デフォルト値の変更 | ログ出力レベルを表します。デフォルト値をWDIAGからWARNに変更します。 |
| log_disk_size | デフォルト値の変更 | CLOGファイルが使用できるディスク容量の上限を表します。デフォルト値を10Gから0に調整します。0はmemory_limitの1/2を使用し、下限は2Gです。 |
| log_disk_utilization_threshold | デフォルト値の変更 | CLOGログディスク利用率(log_disk_sizeに対する割合)のしきい値を表します。このしきい値に達するとログファイルの回収を開始します。デフォルト値を80から0に調整します。0は古いログを即座に回収するポリシーを採用することを意味します。 |
| datafile_size | デフォルト値の変更 | データディスクの初期容量を表します。デフォルト値を2Gから32Mに変更します。 |
| datafile_next | デフォルト値の変更 | データディスクの自動拡張のサイズを表します。デフォルト値を2Gから0に変更します。0はdatafile < 1GBの場合、現在のdatafileを拡張サイズとして倍増させ、データディスクサイズが1GBに達した後は1GBをサイズとして拡張することを意味します。 |
| max_syslog_file_count | デフォルト値の変更 | デフォルトで保持されるシステムログファイルの数を表します。デフォルト値を4から2に変更します。 |
