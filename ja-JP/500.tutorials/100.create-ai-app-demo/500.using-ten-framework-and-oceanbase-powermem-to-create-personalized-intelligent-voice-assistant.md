# TEN-frameworkとOceanBase PowerMemを活用したパーソナライズドスマートエージェント音声アシスタントの構築

このチュートリアルでは、OceanBase PowerMemとTEN-frameworkを組み合わせて、記憶機能を備えたスマートエージェント音声アシスタントを構築する方法を紹介します。TENの強力な「リアルタイムマルチモーダル」機能を統合した上で、「パーソナライズド」対話体験と長期記憶の認識という独自の利点を実現しています。

OceanBase PowerMemの詳細については、[GitHub - oceanbase/powermem](https://github.com/oceanbase/powermem)を参照してください。

## なぜ記憶が必要か？

エージェントに記憶能力が必要なのは、**記憶がパーソナライズされた連続的な対話と深い共感を実現するための核心的基盤**だからです。記憶がなければ、これらのエージェントは「金魚のような記憶」しか持たず、毎回の対話をゼロから始めることになり、真に意味のある関係を築いたり効率的なサービスを提供したりすることはできません。

### 対話の一貫性と文脈理解の維持

**問題**：エージェントがユーザーの過去の発言を覚えていない場合、対話は断絶して繰り返しになり、時にはイライラさせられます。
**例**：

* ユーザー：「最近すごくストレスがたまってて、仕事がもう限界だよ。」
* 数日後に再び言う：「相変わらずだね、プロジェクト終わらないね。」
* もしエージェントが前の対話を覚えていれば、こう言えます：「前にプロジェクトのストレスが大きいって言ってたよね。今も続いてる？少しは楽になった？」
* 記憶がなければ、エージェントはこう聞くかもしれません：「最近どんなストレスがあるの？」——冷たくて繰り返しになります。

記憶により、対話に連続性が生まれ、「本当にあなたを気遣っている人」のように感じさせます。

### 感情的つながりと信頼の構築

感情的な付き合いの本質は「理解されること」と「覚えてもらわれること」です。人間は人間関係において「相手が私のことを覚えている」ということを重視します。

**心理学的研究**によると、覚えてもらった詳細（好み、経験、感情など）は親密感と信頼を大幅に高めます。
**例**：

* 「前に抹茶ラテが好きって言ってたよね。今日はリラックスした話題でリフレッシュしない？」
* このような細部への思い出は、ユーザーに注目されていると感じさせ、感情的価値を高めます。

記憶 = 重視されているサイン → ユーザーの愛着と使用粘着性の向上。

### パーソナライズされたサービスとニーズ予測の実現

アシスタント型エージェントは、ユーザーの習慣に基づいて積極的に支援を提供する必要があります。
**例**：

* ユーザーは毎週の金曜の夜に「明日の天気はどう？」と尋ねます。
* 記憶力のあるエージェントは積極的にリマインドできます：「金曜が近づいてきたね。週末の天気を調べておく？」
* または、ユーザーが会議が多すぎるのを嫌っていることを覚えていて、自動的に提案できます：「来週のスケジュール、すごく詰まってるね。調整してあげる？」

記憶により、エージェントは「受動的な応答」から「能動的な配慮」へと格上げされます。

### 繰り返し質問の回避とユーザーエクスペリエンスの向上

記憶力のないエージェントは同じ質問（例：「あなたの名前は何ですか？」「どこに住んでいますか？」）を繰り返しして、人をイライラさせます。
長期記憶を持つエージェントは以下が可能です：

* ユーザーの名前、好み、重要な出来事（誕生日、記念日）を覚えておく
* 適切なタイミングで気遣いを表現する：「明日はあなたの誕生日ですね。どうやって祝いますか？」

認知的負担を軽減し、ユーザーにより自然で人間味のある体験を提供します。

### 長期的な目標の追跡と成長のサポート

感情的な付き合いや健康アシスタントは、しばしば長期的な目標（ストレス解消、禁煙、学習など）に関わります。
記憶能力は以下に利用できます：

* 進捗の追跡：「今週は3回感情が落ち込んだと記録していますね。先週より2回減っています。進歩しています！」
* 鼓励の提供：「日記を書き続けたいって言ってたよね。今日は書きましたか？」

一回限りのツールではなく、「成長のパートナー」としての役割を形成します。

## OceanBase PowerMemの統合：私たちは何をしましたか？

### ユーザープロファイルメモリモジュール（User Memory Module）

OceanBase PowerMem v0.2.0バージョンでは、**ユーザープロファイルメモリモジュール（User Memory Module）**を新たに導入し、よりスマートでパーソナライズされたエージェントアシスタントを構築するための重要な一歩を踏み出しました。ユーザープロファイルメモリモジュールは、ユーザーの対話内容を自動的に分析し、**ユーザープロファイル（User Profile）**を抽出して永続化します。

**ユーザープロファイル：**ユーザーの現在の状態と特性を記述し、使用嗜好、ロールアイデンティティ、操作習慣、ビジネスニーズなどの重要な属性を含みます。動的更新と長期保存をサポートし、「あなたが誰であるかを覚えておく」ことを実現します。

#### 機能価値

ユーザープロファイルメモリの導入により、Agentは「ステートレスな応答」から「記憶を持つサービス」への飛躍を遂げ、以下の機能向上を実現しました：

* **コンテキスト認識によるインテリジェントな理解**：履歴プロファイルと行動軌跡を組み合わせることで、ユーザーの真の意図をより正確に識別します。
* **パーソナライズドレコメンドとアクティブサービス**：ユーザーの習慣に基づき、よく使われるコマンド、最適化提案、または頻繁に使用される機能の入口をインテリジェントに推薦します。
* **セッション間の連続性体験**：「毎回の対話がゼロから始まる」という制約を破り、複数ラウンドにわたる、時間を超えた一貫したインタラクションを実現します。
* **高度なインテリジェントシナリオのサポート**：今後のインテリジェントな運用保守、セルフサービス診断、パーソナライズドSQL最適化などの高度な機能にデータ基盤を提供し、ユーザーを真に理解するデータベースアシスタントの構築を支援します。

### インテリジェントなメモリ保存戦略

パフォーマンスと一貫性を保証するため、効率的に調整されたメモリ永続化メカニズムを設計しました：

| ポリシー | ルール | 構成パラメータ |
| --- | --- | --- |
| **対話ラウンド数ベース** | `N`ラウンドごとに自動的に保存をトリガーする | `memory_save_interval_turns`（デフォルト5） |
| **アイドルタイムアウトベース** | 連続して`N`秒間操作がない場合、自動的に保存する | `memory_idle_timeout_seconds`（デフォルト30） |

2つの戦略が協働し、重複チェックにより重複書き込みを回避します。同時に、カウンタ同期メカニズムを採用し、並行更新による競合状態を防ぎ、データの一貫性とシステムの安定性を確保します。

### パーソナライズド挨拶の生成

ユーザーに「覚えられている」という温かい体験を感じてもらうため、初回接続時に**パーソナライズドウェルカムグリーティング**機能を導入しました。これにより、毎回のアクセスがより心温まるものになります。

#### 手順

1. **メモリの概要を取得する**：PowerMemからユーザーの過去の対話の概要を検索します。
2. **カスタムグリーティングを生成する**：メモリ情報をプロンプトテンプレートに当てはめ、LLMを呼び出して2〜3文の自然言語で挨拶を生成します。
3. **多言語対応**：ユーザーの地域情報に基づいて、対応する言語（中国語、英語など）を自動選択します。
4. **音声出力**：生成完了後、TTSエンジンにプッシュして再生します。

#### 技術的ハイライト

* **非同期・ノンブロッキング**：全工程が非同期処理であり、ユーザーの通常のアクセスプロセスに影響しません。
* **10秒タイムアウト保護**：LLMの応答遅延が全体の体験に影響するのを防ぎます。
* **ステート分離メカニズム**：独立したフラグビットを使用し、通常の対話と混同するのを避けます。
* **エレガントなフェールオーバー**：過去のメモリが存在しない場合や生成に失敗した場合、自動的に汎用のウェルカムメッセージに戻り、可用性を確保します。

## クイックスタート

### 前提条件

* [https://dashscope.aliyuncs.com/compatible-mode/v1](https://console.agora.io/]にログインし、プロジェクトを作成して `App ID` と `Primary Certificate` を取得します。

    :::tip
    agoraは一定の無料枠を提供していますが、使用量がこの枠を超えると料金が発生する場合があります。続行する前に、公式サイトをご確認いただくか、関連ドキュメントを参照し、料金体系をご確認のうえご同意いただきますようお願いいたします。ご同意いただけない場合は、操作を続けないでください。
    :::

* OpenAI互換モデルサービスのAPIキーを準備します。

    :::tip
    OpenAI互換モデルサービスのAPIキーは、第三者プラットフォームに移動して取得する必要があります。この操作は第三者プラットフォームの料金規則に従い、料金が発生する場合があります。続行する前に、そのプラットフォームの公式サイトをご確認いただくか、関連ドキュメントを参照し、料金体系をご確認のうえご同意いただきますようお願いいたします。ご同意いただけない場合は、操作を続けないでください。
    :::

* seekdbサーバーモードをインストールします。seekdbサーバーモードのデプロイについては、[yum installによるseekdbのデプロイ](../../400.guides/400.deploy/700.server-mode/100.deploy-by-systemd.md)を参照してください。
* Dockerがインストール済みであること。
* Dockerビルドがタイムアウトする可能性があるため、事前にDocker国内ミラーやプロキシを設定しておいてください。

## まとめ

**記憶がAIを「ツール」から「パートナー」へと進化させる。**

私たちはしばしばAIアシスタントを情報検索ツールと見なしますが、真の知能体は「質問に答える」ことにとどまるべきではなく、「人間を理解する」ことに努めるべきです。この点を実現するための核心的な転換点は、まさに**記憶**です。記憶により、インタラクションは断片的なものから解放され、時間の次元と感情の深みを備えるようになります。

今回、OceanBase PowerMemをTEN-frameworkに統合した取り組みは、本質的には「AIの人格化」に関する探求です。私たちはもはや完璧だが無機質な応答マシンを目指すのではなく、ユーザーの行動履歴を認識し、認知を蓄積し、それに基づいて行動を進化させるサービス主体の構築を試みています。

この変化がもたらすのは、単なる体験の向上だけでなく、パラダイムの移行でもあります：

* **応答から共鳴へ**：記憶により、言葉は即時的な刺激の反射ではなく、過去の経験の響きとなります。
* **汎用から専用へ**：同じアシスタントが、異なるユーザーの前で徐々に異なる「性格」を形成していきます。
* **孤立したタスクから継続的な伴侶へ**：サービスの目的は「この対話を完了する」ことから、「あなたの長期的な成長やニーズを支える」ことへと移り変わります。

さらに重要なのは、この仕組みの設計が将来の進化の余地を残している点です。記憶が保存・検索・推論可能になれば、AIは自己修正やユーザーのモデル化を能動的に行う能力の基盤を備えることになります。今日の個別化された挨拶は始まりに過ぎません。明日には、あなたの感情の波を予告し、操作意図を先読みし、あなたが口に出す前に準備を整えて待つパートナーになっているかもしれません。

したがって、この取り組みの意義は「記憶モジュールを追加した」という点にあるのではなく、次の原則を確立したことにあります：
**知能体の価値は、それがどれだけ知っているかではなく、あなたのためにどれだけ覚えているかにある。**

これは人間と機械の関係の本質を変えるだけでなく、次世代のAIシステムに新たな評価基準を定義します。それは精度の高低ではなく、「信頼に値するかどうか」です。
