# セマンティックインデックスを体験する

このチュートリアルでは、seekdbのセマンティックインデックスをすぐに使い始める方法を紹介します。セマンティックインデックスの実際の応用を理解し、数分でその強力な機能を体験できます。手動でベクトルに変換する必要はなく、テキストを直接格納するだけでセマンティック検索が実現できます。

## 概要

セマンティックインデックス（Hybrid Vector Index）とは、テキストを自動的にベクトルに変換してインデックスを構築できるベクトルインデックスであり、seekdbが提供する強力な機能です。これにより、ベクトルの概念がユーザーに対して透過的になります。セマンティックインデックスを使用しないベクトルインデックスと比較して、セマンティックインデックスは使用プロセスを大幅に簡素化します。

* セマンティックインデックスを使用しないベクトルインデックスのプロセス：
    ```shell
    テキスト → 手動で `AI_EMBED` 関数を呼び出してベクトルを生成 → ベクトルを挿入 → ベクトル検索を実行
    ```
* セマンティックインデックスのプロセス：
    ```shell
    テキスト → 直接挿入 → テキスト検索を直接実行
    ```

seekdbは内部でテキストを自動的にベクトルに変換し、インデックスを構築します。検索時も元のテキストを提供するだけで、システムが自動的に埋め込みを行い、ベクトルインデックスで検索するため、使い勝手が大幅に向上します。

## 前提条件

* 管理者に連絡し、該当するデータベース接続文字列を取得した後、以下のコマンドを実行してデータベースに接続します：

    ```shell
    # host: seekdb データベース接続IP。
    # port: seekdb データベース接続ポート。
    # database_name: アクセスするデータベース名。
    # user_name: データベースユーザー名。
    # password: データベースパスワード。
    mysql -h$host -P$port -u$user_name -p$password -D$database_name
    ```

* [AI関数呼び出し権限](../../200.develop/700.ai-function/100.ai-function-permission.md)に関連する権限を持っていることを確認し、データベースで `CREATE_AI_MODEL` および `CREATE_AI_MODEL_ENDPOINT` プログラムを使用して埋め込みモデル（Embedding Model）を登録していることを確認してください：
    :::collapse
    ```sql
    CALL DBMS.AI_SERVICE.DROP_AI_MODEL ('ob_embed');
    CALL DBMS_AI_SERVICE.DROP_AI_MODEL_ENDPOINT ('ob_embed_endpoint');

    CALL DBMS_AI_SERVICE.CREATE_AI_MODEL(
    'ob_embed', '{
        "type": "dense_embedding",
        "model_name": "BAAI/bge-m3"
    }');

    CALL DBMS_AI_SERVICE.CREATE_AI_MODEL_ENDPOINT (
    'ob_embed_endpoint', '{
        "ai_model_name": "ob_embed",
        "url": "https://api.siliconflow.cn/v1/embeddings",
        -- 実際のaccess_keyに置き換えてください
        "access_key": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxx",
        "provider": "siliconflow"
    }');
    ```
    :::

:::info
セマンティックインデックス機能は、現在のバージョンではHNSW/HNSW_BQインデックスタイプのみをサポートしています。
:::

## ステップ１：セマンティックインデックスを作成する

セマンティックインデックスは、**テーブル作成時に作成する**方法と、**後から作成する**方法の2種類があります。

:::info
セマンティックインデックスを作成する際には、<code>VARCHAR</code>列に指定し、埋め込みモデルとベクトル次元数を指定する必要があります。
:::

### テーブル作成時に作成する

```sql
CREATE TABLE items (
    id INT PRIMARY KEY,
    doc VARCHAR(100),
    VECTOR INDEX vector_idx(doc)
    WITH (distance=l2, lib=vsag, type=hnsw, model=ob_embed, dim=1024, sync_mode=immediate)
);
```

### 後からインデックスを作成する

```sql
CREATE TABLE items1 (
    id INT PRIMARY KEY,
    doc VARCHAR(100)
);

CREATE VECTOR INDEX vector_idx
ON items (doc)
WITH (distance=l2, lib=vsag, type=hnsw, model=ob_embed, dim=1024, sync_mode=immediate);
```

## ステップ2：テキストデータを挿入する（手動でのベクトル化は不要）

テキストデータを挿入すると、システムが自動的に埋め込みを行うため、`AI_EMBED` 関数を手動で呼び出す必要はありません。

```sql
INSERT INTO items(id, doc) VALUES(1, 'Rose');
INSERT INTO items(id, doc) VALUES(2, 'Sunflower');
INSERT INTO items(id, doc) VALUES(3, 'Lily');
```

## ステップ3：テキストを使った直接検索を実行する

`semantic_distance` 関数を使用して、生のテキストを渡してベクトル検索を行えば、クエリベクトルを手動で生成する必要はありません。

```sql
SELECT id, doc FROM items
ORDER BY semantic_distance(doc, 'flower')
APPROXIMATE LIMIT 3;
```

結果は次のとおりです：

```sql
+----+-----------+
| id | doc       |
+----+-----------+
|  1 | Rose      |
|  2 | Sunflower |
|  3 | Lily      |
+----+-----------+
3 rows in set
```

システムは、クエリテキスト `'flower'` を自動的にベクトルに変換し、その後ベクトルインデックス内で最も類似したテキストを検索します。

## 上級者向け：ベクトル検索の使用

検索内容のベクトル表現（例えば、`AI_EMBED` 関数で事前に生成されたもの）を既に持っている場合は、これらのベクトルを直接使用してセマンティックインデックスを検索することもでき、毎回の検索で繰り返し埋め込み操作を行う必要がなくなります。

```sql
-- クエリベクトルを取得する
SET @query_vector = AI_EMBED("ob_embed", "flower");

-- ベクトルを使用してインデックス検索を行う
SELECT id, doc FROM items
ORDER BY semantic_vector_distance(doc, @query_vector)
APPROXIMATE LIMIT 3;
```

結果は次のとおりです：

```sql
+----+-----------+
| id | doc       |
+----+-----------+
|  1 | Rose      |
|  2 | Sunflower |
|  3 | Lily      |
+----+-----------+
3 rows in set
```

## まとめ

このチュートリアルを通じて、seekdbのセマンティックインデックスのコア機能を習得しました：

* シンプルな操作プロセス：手動でベクトルに変換する必要はなく、テキストを直接保存するだけでセマンティック検索が実現できます。
* 自動埋め込み：システムがテキストを自動的にベクトルに変換してインデックスを作成するため、検索時には元のテキストのみを提供すれば済みます。
* パフォーマンス最適化：ベクトル検索を直接使用できるため、繰り返しの埋め込み操作を回避します。

セマンティックインデックス機能は、ベクトル検索の操作プロセスを大幅に簡素化し、インテリジェントな検索アプリケーションを構築するのに理想的な選択肢です。
