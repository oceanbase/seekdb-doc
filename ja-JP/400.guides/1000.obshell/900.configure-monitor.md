# モニタリングコンポーネントの設定

obshell Dashboardのパフォーマンス監視およびアラート機能は、PrometheusとAlertmanagerツールに依存しています。本記事では、必要なモニタリングコンポーネントのデプロイ方法について説明します。

## 背景

obshell Dashboardのパフォーマンス監視機能はobagentおよびPrometheusツールに依存し、アラート機能はAlertmanagerツールに依存します。obagentはHTTPインターフェースを提供し、seekdbからデータを収集できます。Prometheusは設定に基づいて定期的にobagentのインターフェースにアクセスし、監視データを収集して永続化ストレージに保存します。obshell Dashboardは、Prometheusが収集した監視データを表示するページを提供します。Alertmanagerは、Prometheusなどの監視システムからのアラートを処理し、アラートの重複除去、グループ化、ルーティング、サイレンシングなどの機能を提供します。

## obagentのインストール

### seekdbの設定

1. ユーザーの準備

   OceanBaseデータベースに対する読み取り権限のみを付与した、読み取り専用ユーザーの使用を推奨します。

   ```shell
    create user monitor identified by '******';
    grant select on oceanbase.* to monitor;
   ```

2. インスタンス名の設定

   Prometheusを使用して複数のseekdbインスタンスを監視する場合は、各seekdbインスタンスに異なるインスタンス名を設定し、インスタンス間を区別しやすくします。

   ```shell
   alter system set `cluster` = 'obcluster';
   ```

   :::tip
      インスタンス名を設定する際は、構成パラメータ<code>cluster</code>にバッククォート(<code>`</code>)を付加する必要があります。
   :::

### obagentの設定

1. obagentのインストール

   [オープンソースイメージレジストリ](https://mirrors.aliyun.com/oceanbase/community/stable/)にアクセスし、ご利用の環境のアーキテクチャに対応するobagentインストールパッケージをダウンロードして、以下のコマンドでインストールします。最新バージョンのインストールを推奨します。

   ```shell
   [root@test ~]# rpm -ivh obagent-*.rpm
   ```

   obagentはデフォルトで `/home/admin` ディレクトリにインストールされます。

2. obagentの設定

   以下のコマンドを実行して、収集アカウントのパスワードおよび必要なメタデータ情報を設定します。

   ```shell
   [root@test ~]# cd /home/admin/obagent
   [root@test obagent]# bin/ob_agentctl config --update monagent.ob.monitor.user=monitor,monagent.ob.monitor.password=******,monagent.ob.cluster.name=obcluster,monagent.pipeline.ob.status=active,agent.http.basic.auth.metricAuthEnabled=false
   ```

   コマンドパラメータの説明は以下のとおりです：

   * `monagent.ob.monitor.user`：収集アカウントを設定します。seekdbで作成された読み取り専用ユーザー（本記事では`monitor`）を指定します。
   * `monagent.ob.monitor.password`：収集アカウントのパスワードを設定します。seekdbの読み取り専用ユーザーのパスワードを指定します。
   * `monagent.ob.cluster.name`：seekdbインスタンスのインスタンス名です。インスタンスに接続後、`SHOW PARAMETERS LIKE 'cluster';` コマンドを実行して確認できます。`value`列の値がインスタンス名です。
   * `monagent.pipeline.ob.status`：`active`に設定すると、seekdb関連メトリクスの収集が有効になります。
   * `agent.http.basic.auth.metricAuthEnabled`：`false`に設定すると、obagent HTTPインターフェースのBasic Auth認証が無効になります。

   コマンドの実行出力は次のとおりです：

   ```shell
   {"successful":true,"message":"success","error":""}
   ```

3. obagentの起動

   ```shell
   [root@test obagent]# bin/ob_agentctl start
   ```

   コマンドの実行出力は次のとおりです：

   ```shell
   {"successful":true,"message":"ok","error":""}
   ```

## Prometheusの設定

[Prometheus公式サイト](https://prometheus.io/)または[オープンソースミラーコレクション](https://mirrors.aliyun.com/oceanbase/community/stable/)にアクセスし、ご利用環境のアーキテクチャに応じた対応するインストールパッケージをダウンロードしてPrometheusをデプロイします。通常、すべてのseekdbインスタンスを監視するには、1つのPrometheusインスタンスだけで十分です。このセクションで提供されている設定例は参考用です。具体的なインストールおよび設定の詳細については、[Prometheus公式ドキュメント](https://prometheus.io/docs/prometheus/latest/getting_started/)を参照してください。

:::info
   obdの<a href="https://github.com/oceanbase/obdeploy/blob/master/plugins/prometheus/2.37.1/prometheus_rules.yaml">GitHubリポジトリ</a>にアクセスすると、OceanBaseが提供するPrometheusアラートルールファイルを確認できます。
:::

```shell
global:
  scrape_interval: 5s # スクレイピング間隔を15秒に設定します。デフォルトは1分です。
  evaluation_interval: 5s # ルールの評価間隔を15秒に設定します。デフォルトは1分です。

# Alertmanager configuration, prometheus will push alerts to these addresses
alerting:
  alertmanagers:
    - static_configs:
      - targets:
        - localhost:9093

# Rule files are loaded once and then evaluated periodically according to the global 'evaluation_interval'.
rule_files:
  - "prometheus_rules.yaml"
  # - "second_rules.yml"

scrape_configs:
  - job_name: "ob-basic"
    metrics_path: "/metrics/ob/basic"
    # prometheus 3.x系では以下の設定を有効にする必要があります
    # fallback_scrape_protocol: PrometheusText0.0.4
    static_configs:
      - targets: ["127.0.0.1:8088"]
  - job_name: "ob-extra"
    metrics_path: "/metrics/ob/extra"
    # prometheus 3.x系では以下の設定を有効にする必要があります
    # fallback_scrape_protocol: PrometheusText0.0.4
    static_configs:
      - targets: ["127.0.0.1:8088"]
  - job_name: "ob-host"
    metrics_path: "/metrics/node/host"
    # prometheus 3.x系では以下の設定を有効にする必要があります
    # fallback_scrape_protocol: PrometheusText0.0.4
    static_configs:
      - targets: ["127.0.0.1:8088"]
```

Prometheusの設定後、Prometheusのグラフィカルインターフェースにアクセスし、**Status**をクリックして**Target**を選択すると、データ収集が正常に行われているかどうかを確認できます。

:::

### Alertmanagerの設定

[Prometheus公式Webサイト](https://prometheus.io/)または[オープンソースイメージレジストリ](https://mirrors.aliyun.com/oceanbase/community/stable/)にアクセスし、使用環境のアーキテクチャに対応するインストールパッケージをダウンロードして解凍します。[Alertmanagerドキュメント](https://prometheus.io/docs/alerting/latest/configuration/)を参照して設定ファイル(`alertmanager.yml`)を修正し、完了後に作業ディレクトリに移動して以下のコマンドを実行してAlertmanagerを起動します。

```shell
[root@test alertmanager]# nohup ./alertmanager --config.file=alertmanager.yml --cluster.advertise-address=127.0.0.1:9093 > alertmanager.log 2>&1 &
```

例では、`127.0.0.1:9093` がサービスアドレスを表し、nuohup は alertmanager プロセスをバックグラウンドで実行することを示します。
