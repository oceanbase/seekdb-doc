# ディスクの計画

seekdbサーバーは、データディスク、トランザクションログディスク、およびseekdbのインストールディスクに依存します。個人ユーザーの場合は、すべてのデータを1つのディスクに配置することができ、この手順をスキップできます。企業ユーザーの場合は、データを3つの異なるディスクにそれぞれマウントすることを推奨します。

マシンに3つのディスクがない場合、またはRAIDディスクアレイを使用している場合は、ディスクまたはディスクアレイの論理ボリュームをパーティション分割する必要があります。以下の方式でパーティション分割することを推奨します：

* データディスク

  データディスクはベースラインデータの格納に使用され、パスは構成パラメータ`data_dir`で指定されます。seekdbを初めて起動する際、`${data_dir}/{sstable,slog}`が自動的に作成されます。データディスクのサイズは`datafile_disk_percentage`/`datafile_size`パラメータによって決定され、デプロイ後は`datafile_next`および`datafile_maxsize`構成パラメータを使用してディスクファイルの動的拡張を行うこともできます。詳細については、[ディスクデータファイルの動的拡張の設定](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001971412)を参照してください。

* トランザクションログディスク

  トランザクションログディスクのパスは構成パラメータ`redo-dir`で指定されます。トランザクションログディスクのサイズは、seekdbメモリの3倍から4倍以上に設定することを推奨します。seekdbを初めて起動する際、`${redo-dir}`が自動的に作成されます。トランザクションログディスクには複数の固定サイズのファイルが含まれており、必要に応じてトランザクションログを自動的に作成および削除できます。トランザクションログがディスク容量の80%に達すると、自動削除がトリガーされます。ただし、トランザクションログに対応するメモリデータが既にベースラインデータにマージされている場合にのみ、トランザクションログは削除されます。

  同一のデータ量の場合、トランザクションログのサイズはメモリデータサイズの約3倍です。したがって、トランザクションログディスクに必要な空き容量の上限は、2回のメジャーコンパクション後のデータ総量に比例します。経験則：トランザクションログファイルサイズ = 増分データメモリ上限の3～4倍。

* seekdbインストールディスク

  seekdbインストールディスクのパスは構成パラメータ`base-dir`で指定されます。seekdbのRPMパッケージのインストールディレクトリは`${base-dir}`配下にあります。ここでは、ベースラインデータファイルとトランザクションログファイルが、それぞれ独立したデータディスクとトランザクションログディスクを指すソフトリンクとして設定されます。seekdbの実行ログは`${base-dir}/log`配下にあります。実行ログは継続的に増加し、seekdbは実行ログを自動的に削除できないため、定期的に実行ログを削除する必要があります。

## ディスクのマウント

seekdbのディスクマウントポイント要件は以下の表のとおりです。

* 個人ユーザー

   個人ユーザーの場合、ディスクをマウントしなくても構いませんが、使用時にはディスク容量が5GB以上あることを推奨します。

* 企業ユーザー

   |    ディレクトリ     |       サイズ       |       用途       |         ファイルシステム形式          |
   |------------|----------------|----------------|-------------------------|
   | /home      | 100 GB\~300 GB | seekdbデータベースインストールディスク | ext4またはxfsを推奨 |
   | /data/log1 | seekdbに割り当てるメモリサイズの2倍   | seekdbプロセスログディスク   | ext4またはxfsを推奨 |
   | /data/1    | 保存するデータサイズによる   | seekdbプロセスデータディスク   | ext4またはxfsを推奨 |

   :::info
      <ul><li>ルートディレクトリは50GB以上を推奨します。LVMを使用する場合は、作成時にストライピングパラメータを使用することを推奨します。例：<code>lvcreate -n data -L 3000G obvg --stripes=3 --stripesize=128</code></li>
      <li>本番環境では、データディスクとログディスク、インストールディスクを異なるディスクに分けることで、パフォーマンスの問題を回避することを推奨します。</li></ul>
   :::

## ディスクのマウント操作

ディスクのマウントはrootユーザーで実行する必要があり、以下の2つの方法があります：

* LVMツールを使用してディスクをマウントする（推奨）
* fdiskツールを使用してディスクをマウントする

### LVMツールを使用してディスクをマウントする

1. ディスク情報の確認

    fdisk -l コマンドを使用して利用可能なディスクとパーティションを特定し、ターゲットデバイス（例：/dev/sdb1）を確認します。

    ```shell
    fdisk -l
    ```

2. LVMツールのインストール

    LVMが事前にインストールされていない場合は、以下のコマンドを実行してLVMをインストールします。既にインストール済みの場合は、この手順をスキップしてください。

    * Debian/Ubuntu系システム

      ```shell
      apt-get install lvm2
      ```

    * CentOS/RHEL系システム

      ```shell
      yum install lvm2
      ```

3. 物理ボリューム（PV）の作成

   1. パーティションを物理ボリュームに初期化します。

      ```shell
      pvcreate /dev/sdb1
      ```

   2. PVの作成結果を確認します。

      ```shell
      pvs
      ```

4. ボリュームグループ（VG）の作成

   1. 複数の物理ボリュームを1つのVGに統合します。

      ```shell
      vgcreate vg01 /dev/sdb1 /dev/sdc1
      ```

   2. VG情報を確認します。

      ```shell
      vgs
      ```

5. 仮想ボリューム（LV）の作成

   1. VGから100GのLVを割り当てます。

      ```shell
      lvcreate -L 100G -n lv01 vg01
      ```

      ここでのLVのサイズは実際の状況に応じて設定できます。

   2. LV情報を確認します。

      ```shell
      lvs
      ```

6. フォーマットとマウント

   1. ext4ファイルシステムにフォーマットします。

      ```shell
      mkfs.ext4 /dev/vg01/lv01
      ```

   2. マウントポイントを作成します。

      ```shell
      mkdir -p /data/1
      ```

   3. 一時的にマウントします。

      ```shell
      mount /dev/vg01/lv01 /data/1
      ```

7. システム起動時の自動マウントの設定

    `/etc/fstab` ファイルを編集し、マウント設定を追加します：

    ```shell
    vim /etc/fstab
    ```

    設定ファイルに以下の内容を追加します：

    ```shell
    /dev/vg01/lv01  /data/1  ext4  defaults,noatime,nodiratime,nodelalloc,barrier=0  0  0
    ```

### fdiskツールを使用してディスクをマウントする

1. ディスク情報の確認

    fdisk -l コマンドを使用して利用可能なディスクとパーティションを特定し、ターゲットデバイス（例：/dev/sdb1）を確認します。

    ```shell
    fdisk -l
    ```

2. パーティションの作成

    fdiskツールを使用して新しいパーティションを作成します。例えば、`fdisk /dev/sdb1` と入力し、n を押してパーティションを作成し、最後に w を押して保存します。

    ```shell
    fdisk /dev/sdb1
    ```

3. フォーマットとマウント

   1. ext4ファイルシステムにフォーマットします。

      ```shell
      mkfs.ext4 /dev/sdb1
      ```

   2. マウントポイントを作成します。

      ```shell
      mkdir -p /data/1
      ```

   3. 一時的にマウントします。

      ```shell
      mount /dev/sdb1 /data/1
      ```

4. システム起動時の自動マウントの設定

    `/etc/fstab` ファイルを編集し、マウント設定を追加します：

    ```shell
    vim /etc/fstab
    ```

    設定ファイルに以下の内容を追加します：

    ```shell
    /dev/sdb1  /data/1  ext4  defaults,noatime,nodiratime,nodelalloc,barrier=0  0  0
    ```

## ディスクの確認

ディスクをマウントした後、以下のコマンドを実行してディスクのマウント状況を確認します：

```shell
df -h
```

次のような結果が返されます：

```shell
Filesystem      Size  Used Avail Use% Mounted on
devtmpfs         31G     0   31G   0% /dev
tmpfs            31G     0   31G   0% /dev/shm
tmpfs            31G  516K   31G   1% /run
tmpfs            31G     0   31G   0% /sys/fs/cgroup
/dev/vda1       493G  171G  302G  37% /
tmpfs           6.2G     0  6.2G   0% /run/user/0
/dev/sdb1     984G    77M  934G  1%  /data/1
/dev/vdc1     196G     61M   186G  1%  /data/log1
/dev/vdb1     492G    73M   467G  1%  /home/admin/seekdb
```

結果の説明

* `/data/1` はデータディスクで、サイズは1TBです。

* `/data/log1` にはログが保存されます。

* `/home/admin/seekdb` にはseekdbのバイナリファイルと実行ログが保存されます。

設定ファイル内の `data_dir`、`redo_dir`、`home_path` に対応するディスクがマウント済みであることを確認してください。`data_dir` および `redo_dir` の対応するディレクトリは空でなければならず、`data_dir` のディスク使用率は4%未満でなければなりません。

## ディレクトリ権限の設定

ディスクのマウントが完了したら、ディスクのマウント先ディレクトリの権限を確認する必要があります。

以下のコマンドを実行して、関連するファイルディレクトリの権限を確認します。

   ここでは `data` ディレクトリを例に説明します：

   ```shell
   ls -al
   ```

   次のような結果が返されます：

   ```shell
   drwxr-xr-x 2 admin admin 4096 Feb 9 18:43 .
   drwxr-xr-x 2 admin admin 4096 Feb 9 18:43 log1
   ```

   ディレクトリ権限を確認した後、`admin` ユーザーに関連ファイルの権限がない場合は、以下のコマンドを実行してファイルの所有者を変更できます：

   ```shell
   chown -R admin:admin /data/log1
   chown -R admin:admin /data
   ```

   ここでは `/data/log1`、`/data` が例として挙げたマウントディレクトリです。実際のマウントディレクトリに合わせて置き換えてください。
