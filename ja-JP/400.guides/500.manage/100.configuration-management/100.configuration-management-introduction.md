# 設定管理の紹介

seekdbは、構成パラメータとシステム変数を設定することで、設定管理を実現します。

## 構成パラメータ

構成パラメータは主に運用保守に使用され、マシンやそれ以上のレベルのシステム動作を制御するために一般的です。起動パラメータとして指定するほか、実行時に変更してシステム動作を調整することもできます。

## システム変数

システム変数は通常、ユーザーセッションにバインドされ、セッションレベルのSQL動作を制御します。

グローバルレベルとセッションレベルの変数の設定をサポートしています。グローバルレベルのシステム変数を設定しても、現在のセッションには反映されませんが、新規作成されるすべてのセッションは新しい変数値を読み取ることができます。セッションレベルのシステム変数を設定すると、その変更は現在のセッション内でのみ有効になります。

## システム構成パラメータとシステム変数の比較

| 比較項目   | システムパラメータ  | システム変数|
| -------- | ---------- | ---------- |
| 適用範囲 | インスタンス | グローバルまたはセッションレベル。 |
| 適用方法 | <ul><li>動的反映：`edit_level`が`dynamic_effective`の場合。</li><li>再起動後に反映：`edit_level`が`static_effective`の場合。</li></ul>  | <ul><li>セッションレベルの変数を設定しても、現在のセッションのみに有効で、他のセッションには反映されません。</li><li>グローバルレベルの変数を設定しても、現在のセッションには無効です。有効にするには、再ログインして新しいセッションを確立する必要があります。</li></ul> |
| 変更方法 | <ul><li>SQLステートメントを使用して変更できます。例：<br/> `Alter SYSTEM SET schema_history_expire_time='1h';` </li><li>起動パラメータを使用して変更できます。例：<br/> `/usr/bin/observer --base-dir /var/lib/oceanbase-lite --schema_history_expire_time='1h'`   </li></ul> | SQLステートメントを使用した変更のみサポートします。例：<br/> `SET ob_query_timeout = 20000000;`<br/> `SET GLOBAL ob_query_timeout = 20000000;`   |
| ライフサイクル | 長く、プロセスの起動から終了まで持続します。| 短く、スキーマ作成が完了して初めて有効になります。 |
| クエリ方法 | `SHOW PARAMETERS`ステートメントを使用してクエリできます。例：<br/>` SHOW PARAMETERS LIKE 'schema_history_expire_time';`| `SHOW [GLOBAL] VARIABLES`または`SELECT`ステートメントを使用してクエリできます。例：`SHOW VARIABLES LIKE 'ob_query_timeout';`<br/> `SHOW GLOBAL VARIABLES LIKE 'ob_query_timeout';` <br/>`SELECT * FROM INFORMATION_SCHEMA.SESSION_VARIABLES WHERE VARIABLE_NAME = 'ob_query_timeout';`<br/>`SELECT * FROM INFORMATION_SCHEMA.GLOBAL_VARIABLES WHERE VARIABLE_NAME = 'ob_query_timeout';` |
