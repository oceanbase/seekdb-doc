# ログイン失敗処理

複数回のログイン失敗を試みたユーザーに対して、seekdbはそのユーザーをロックし、悪意のあるパスワード攻撃を防ぎ、データベースを保護してセキュリティを向上させます。

## ログイン失敗処理ポリシー

seekdbは、パラメータ`connection_control_failed_connections_threshold`を使用してユーザーの誤ログイン試行のしきい値を制御します。ユーザーの連続する誤ログイン回数がこのパラメータで定義された値を超えると、システムはアカウントをロックします。

`connection_control_failed_connections_threshold`パラメータは、ユーザーの誤ログイン試行のしきい値を指定するために使用されます。デフォルト値は`0`で、取り得る範囲は\[0，2147483647\]です。具体的には：

* 値が`0`の場合、この機能は無効であり、ユーザーの誤ログイン試行は処理されません。

* 値が`0`以外の場合、ユーザーの誤ログイン回数が指定された値を超えると、システムはアカウントをロックします。ロック時間は以下の式で計算されます：

  `MIN(MAX((current_failed_login_num + 1 - connection_control_failed_connections_threshold) * 1000, connection_control_min_connection_delay), connection_control_max_connection_delay)`

  ここで：

  * `current_failed_login_num`は、ユーザーの現在の連続誤ログイン回数を表し、`current_failed_login_num`は`connection_control_failed_connections_threshold`以上です。

  * パラメータ`connection_control_min_connection_delay`は、連続誤ログイン回数のしきい値を超えた後のロック時間の最小値を指定するために使用されます。取り得る範囲は\[1000，2147483647\]で、デフォルト値は`1000`ミリ秒です。

    パラメータ`connection_control_min_connection_delay`の詳細については、[connection_control_min_connection_delay](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015592)を参照してください。

  * パラメータ`connection_control_max_connection_delay`は、連続誤ログイン回数のしきい値を超えた後のロック時間の最大値を指定するために使用されます。取り得る範囲は\[1000，2147483647\]で、デフォルト値は`2147483647`ミリ秒です。

    パラメータ`connection_control_max_connection_delay`の詳細については、[connection_control_max_connection_delay](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015519)を参照してください。

## 設定例

1. `root`ユーザーでseekdbにログインします。

   ```shell
   mysql -h127.0.0.1 -uroot -P2881
   ```

2. 以下のステートメントを実行し、ユーザーの誤ログイン試行回数を5回に設定します。誤ログイン回数を超えた場合のロック時間の最小値を60000ミリ秒、最大値を360000ミリ秒に指定します。

   例：

   ```shell
   ALTER SYSTEM SET connection_control_failed_connections_threshold=5;

   ALTER SYSTEM SET connection_control_min_connection_delay=60000;

   ALTER SYSTEM SET connection_control_max_connection_delay=360000;
   ```

   パラメータの詳細な設定と説明については、[パラメータの変更](../../100.configuration-management/200.system-configuration-items/300.modify-parameters.md)を参照してください。

3. ログインユーザーを作成します。

   ```shell
   CREATE USER 'test' IDENTIFIED BY '*******';
   ```

   ```shell
   Query OK, 0 rows affected (0.04 sec)
    ```

4. ログイン失敗処理ポリシーが有効になっているか確認します。

   連続して5回間違ったパスワードを入力すると、ユーザーはロックされます。

   ```shell
   mysql -h127.0.0.1 -uroot -P2881 -p*******;
   ERROR 5039 (01007): User locked
   ```

   `root`ユーザーでseekdbにログインし、失敗したログイン情報を確認します。

   ```shell
   SELECT * FROM information_schema.CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS;
   ```

   ```shell
   +-------------+-----------------+
   | USERHOST    | FAILED_ATTEMPTS |
   +-------------+-----------------+
   | 'test'@'%' |               5 |
   +-------------+-----------------+
   1 row in set (0.005 sec)
   ```

5. 以下のSQLステートメントを実行して、ユーザーのロックを解除します。

   :::tip
   ユーザーのロック解除操作は通常、管理者が実行します。一般ユーザーがロックおよびロック解除操作を実行する必要がある場合は、グローバルな`ALTER USER`権限が付与されていなければなりません。ユーザー権限の確認および権限付与に関する操作については、[ユーザー権限の確認](../300.access-control/200.user-and-permission/400.view-user-permissions.md)および[直接権限付与](../300.access-control/200.user-and-permission/200.direct-authority.md)を参照してください。
   :::

      ```shell
         ALTER USER test ACCOUNT UNLOCK;
      ```

      ```shell
         Query OK, 0 rows affected (0.03 sec)
      ```
