# mysqldumpを使用したseekdbのアップグレード

mysqldumpによる論理移行を利用してseekdbをアップグレードできます。

:::info

OceanBase OBLOADER/OBDUMPERを使用した論理移行によるseekdbのアップグレードもサポートされています。OceanBase OBLOADER/OBDUMPERの詳細な使用方法については、[OceanBase OBLOADER/OBDUMPERの紹介](https://en.oceanbase.com/docs/common-oceanbase-dumper-loader-10000000003281154)を参照してください。

:::

## mysqldump

mysqldumpはMySQLで最も一般的に使用される論理的なインポートおよびエクスポートツールであり、主にデータベースのダンプに使用されます。

mysqldumpのバックアップ原理は、プロトコルを介してデータベースに接続した後、バックアップが必要なデータをクエリし、クエリされたデータを対応する`INSERT`ステートメントに変換することです（論理的エクスポート）。

データを復元する際は、エクスポートファイル内のSQLステートメントを実行するだけです（論理的インポート）。この方法により、異なるデータベース間でデータ移行を行うことができます。

## アップグレード前の準備

* アップグレードする前に、新バージョンのseekdbをデプロイ済みであることを確認してください。

* mysqldumpがインストールされていること。

    推奨バージョン：

    | システム   |                             バージョン                              |
    |-------|-------------------------------------------------------------|
    | Linux | mysqldump Ver 10.13 Distrib 5.6.37, for Linux (x86_64)      |
    | MacOS | mysqldump Ver 10.13 Distrib 5.7.21, for macos10.13 (x86_64) |

## アップグレード

### データのバックアップ

1. 古いバージョンのseekdbにログインします。

    ```shell
    mysql -h127.0.0.1 -uroot -P2881 -p****** -A
    ```

    ここで使用されているホストとポート情報はすべて古いバージョンのseekdbのものです。

2. SQL実行のタイムアウト時間を設定します。

    ```shell
    SET GLOBAL ob_trx_timeout=1000000000,GLOBAL ob_query_timeout=1000000000;
    ```

3. データをエクスポートします。

    最終的にデータは`backup.sql`ファイルにバックアップされます。

    ```shell
    mysqldump -h`host` -P`port` -uroot  --skip-triggers --databases `database-name` --skip-extended-insert > ./backup.sql
    ```

    :::tip
    一部のデフォルトオプションについては、パラメータの前に`--skip`を使用することで、対応する効果を無効化またはキャンセルできます。
    :::

    | パラメータ | パラメータ略称 | 必須 | 説明 | 例 |
    |----|------|------|-------|----|
    | --host   | -h   | はい    | サーバーのIPアドレス     | -h127.0.0.1 |
    | --port  | -P   | はい    | サーバーのポート番号 | -P2881 |
    | --user | -u   | はい    | ユーザー名 | -uroot |
    | --password  | -p   | いいえ    | パスワード   |   |
    | --databases    | なし    | はい    | データベースを指定します。`--all-databases`はすべてのデータベースをエクスポートすることを意味しますが、使用は推奨されません。個別に指定することをお勧めします。実際の使用では、データベース名を直接入力できます。| test  |
    | --skip-triggers        | なし    | いいえ    | トリガーを無効にします。 | --skip-triggers  |
    | --skip-extended-insert | なし    | いいえ    | エクスポート文は複数の`INSERT`形式である場合、それ以外の場合は`INSERT INTO table VALUES(...),(...),`形式です。  | --skip-extended-insert     |
    | \> | なし    | はい    | 保存パスを指定します      | \> /backup/mysqldump/alldb.sql   |

    その他の一般的なパラメータ：

    | パラメータ | パラメータ略称 | 必須 | 説明 | 使用例 |
    |-----|------|------|------|-------------------|
    | -d                | なし    | いいえ    | テーブル構造のみをエクスポートし、データはエクスポートしません。  | -d                |
    | -t                | なし    | いいえ    | CREATE TABLEステートメントを追加せずに、データのみをエクスポートします。 | -t                |
    | --compact         | なし    | いいえ    | 圧縮モードで、より少ない出力を生成します。  | --compact         |
    | --comments        | なし    | いいえ    | コメント情報を追加します。  | --comments        |
    | --complete-insert | なし    | いいえ    | 完了した挿入ステートメントを出力します。 | --complete-insert |
    | --force           | なし    | いいえ    | エラーを無視します。 | --force           |
    | --lock-tables     | なし    | いいえ    | エクスポート中にデータベースをロックします。 --skip-lock-tables：エクスポート中にデータベースをロックしません。現在のseekdbバージョンでは、どのパラメータを使用しても、エクスポート中にデータベースはロックされません。 | --lock-tables     |

    より詳細なパラメータについては、mysqldump --helpを参照してください。

    **よく使われる例**

    * すべてのデータベースをバックアップ：

      ```sql
      mysqldump -h127.0.0.1 -P2881 -uroot -p --all-databases > /backup/mysqldump/alldb.sql
      ```

    * 指定データベースtestをバックアップ：

      ```sql
      mysqldump -h127.0.0.1 -P2881 -uroot -p test > /backup/mysqldump/test.sql
      ```

    * 指定データベースの指定テーブルtable1, table2をバックアップ。(複数のテーブルはスペースで区切る)

      ```shell
      mysqldump -h127.0.0.1 -P2881 -uroot -p  mysql table1 table2 > /backup/mysqldump/table2.sql
      ```

    * 指定データベースから特定のテーブルを除外してバックアップ

      ```sql
      mysqldump -h127.0.0.1 -P2881 -uroot -p test --ignore-table=test.t1 --ignore-table=test.t2 > /backup/mysqldump/test2.sql
      ```

### データの復元

* 古いバージョンのseekdbが配置されているサーバーから新しいバージョンのseekdbに直接アクセスできる場合、データを直接復元できます。

    1. 新しいバージョンのseekdbにログインします。

        ```shell
        mysql -h`new-host` -P`new-port` -uroot -Ac
        ```

    2. データをインポートします。

        ```shell
        source backup.sql;
        ```

* 古いバージョンのseekdbが配置されているサーバーから新しいバージョンのseekdbに直接アクセスできない場合、まずバックアップデータを新しいバージョンのseekdbが配置されているサーバーにコピーし、その後データの復元を実行する必要があります。

    1. 新しいバージョンのseekdbにログインします。

        ```shell
        mysql -h`new-host` -P`new-port` -uroot -Ac
        ```

    2. データをインポートします。

        ```shell
        source backup.sql;
        ```

## よくある質問

**データ処理タイムアウト**

エクスポートするデータ量が多い場合、`TIMEOUT 4012` エラーが発生する可能性があります。このエラーを回避するには、データベースにログインして以下のステートメントを実行し、システムパラメータを調整してください。エクスポート完了後、元の値に戻すことができます。

```shell
mysqldump: Error 4012: Timeout, query has reached the maximum query timeout: 10000000(us), maybe you can adjust the session variable ob_query_timeout or query_timeout hint, and try again.
```

システムパラメータを調整します。

```shell
SET GLOBAL ob_trx_timeout=1000000000,GLOBAL ob_query_timeout=1000000000;
```
