# データのインポート

seekdbは、外部ファイルのデータをデータベーステーブルにインポートすることをサポートしており、サーバー側からのインポートとクライアント側からのインポートの2つの方法を提供しています。このドキュメントでは、これら2つのインポート方法の具体的な使用方法について説明します。

## 概要

データファイルの読み取り位置に応じて、seekdbは以下の2つの主要なデータインポート方法をサポートしています：

1. **サーバー側からのインポート（推奨）**：データファイルがサーバーからアクセス可能な場所（ローカルファイルシステム、オブジェクトストレージなど）にある場合、データベースサーバーが直接ファイルを読み取ってインポートします。本番環境や大規模なインポートに適しています。サーバー側からのインポートは **FILES() 関数** に基づいており、`LOAD DATA FROM FILES()` と `INSERT INTO ... SELECT FROM FILES()` の2つの使用方法があります。

2. **クライアント側からのインポート**：データファイルがクライアント側のローカルにある場合、クライアントツールでファイルを読み取り、サーバーに転送します。この方法は、サーバーとファイルの場所を結ぶネットワークが接続されていない場合に適しています。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>seekdbでは、サーバー側からのインポート方式を優先的に使用することを推奨します。サーバー側からのインポートはパフォーマンスが優れており、クライアントの設定に依存しません。クライアント側からのインポート方式は、サーバーがファイルの場所に直接アクセスできない場合に適しています。</p>
  <p>本記事では、<code>LOAD DATA</code> ステートメントを使用したデータインポートの方法を簡単な例で説明します。<code>LOAD DATA</code> 関連構文の詳細については、<a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004479542">LOAD DATA</a> ドキュメントを参照してください。</p>
</main>

## 使用上の制限

トリガー(Trigger)を持つテーブルでは、`LOAD DATA`ステートメントの使用は禁止されています。

## 注意点

seekdbは、パラレル処理技術によりデータインポートのレートを最適化します。この操作では、データを複数のサブタスクに分割して並列実行し、各サブタスクは独立したトランザクションとして扱われるため、実行順序は固定されていません。そのため、以下の点にご注意ください。

* データインポートプロセス全体のグローバルな原子性は保証されません。
* 主キーがないテーブルについては、データの書き込み順序が元のファイルの順序と異なる場合があります。

## インポート権限の取得

データインポート操作を実行する前に、対応する権限を取得しておく必要があります。実行権限を付与する手順は以下のとおりです：

1. ユーザーに `FILE` 権限を付与します。

   ```sql
   GRANT FILE ON *.* TO user_name;
   ```

   ここで、`user_name` はインポートコマンドを実行するユーザーです。

2. テーブルに `INSERT` 権限を付与します。

   ```sql
   GRANT INSERT ON database_name.tbl_name TO user_name;
   ```

   ここで、`database_name` はデータベース名、`tbl_name` はテーブル名、`user_name` はインポートコマンドを実行するユーザーです。

3. `secure_file_priv` システム変数を設定し、ファイルへのインポートまたはエクスポート時にアクセス可能なパスを制御します（サーバー側からのインポート方式のみ必要）。

   <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>セキュリティ上の理由により、システム変数 <code>secure_file_priv</code> を設定する際は、ローカルソケット接続を介してデータベースに接続し、このグローバル変数を変更するSQLステートメントを実行する必要があります。</p>
   </main>

   **例：**

   ファイルが配置されているディレクトリを `/` に設定すると、制限がなく、任意のパスにアクセスできることを意味します。詳細については、[secure_file_priv](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004478743)を参照してください。

   ```sql
   SET GLOBAL SECURE_FILE_PRIV = "/";
   ```

## サーバー側からのインポート（推奨）

サーバー側からのインポートは、seekdbが推奨するデータインポート方法であり、サーバーからアクセス可能なファイル場所（ローカルファイルシステム、オブジェクトストレージなど）から直接データをインポートできます。

サーバー側からのインポートは **FILES() 関数** を基にしており、seekdbはFILES() 関数を使用したデータインポートの2つの方法を提供しています：

1. **`LOAD DATA FROM FILES()`**：データインポート専用のステートメントで、直接インポートのシナリオに適しています。
2. **`INSERT INTO ... SELECT FROM FILES()`**：標準のINSERT SELECT構文とFILES() 関数を組み合わせることで、より柔軟なデータ処理機能を提供します。

本記事では、簡単な例を用いて、上記の2つの方法を使用したデータインポートの手順を紹介します。

### 方法1：LOAD DATA FROM FILES()を使用する

1. データファイルを準備し、サーバーからアクセス可能な場所に配置します。

   1. サーバー上にデータファイルのディレクトリを作成し、テストデータを準備します：

        ```shell
        mkdir -p /home/admin/test_data
        ```

   2. エディタを使用してファイルを作成します：

        ```shell
        vi /home/admin/test_data/student.csv
        ```

   3. ファイルに以下の内容を追加します：

        ```csv
        1,lin,98
        2,hei,90
        3,ali,95
        ```

2. 対象テーブルを作成します。

   ```sql
   CREATE TABLE student (id INT, name VARCHAR(50), score INT);
   ```

3. `LOAD DATA FROM FILES()` ステートメントを使用してデータをインポートします。

   ```sql
   LOAD DATA FROM FILES(
       LOCATION = '/home/admin/test_data/',
       FORMAT = (
           TYPE = 'csv',
           FIELD_DELIMITER = ','),
       PATTERN = 'student.csv')
       INTO TABLE student;
   ```

   パラメータ説明：
   * `LOCATION`：ファイルがあるディレクトリのパスを指定します。
   * `FORMAT`：ファイル形式を指定します。`TYPE = 'csv'` はCSV形式を意味し、`FIELD_DELIMITER` は列区切り文字をカンマと指定します。
   * `PATTERN`：ファイルのマッチングパターンを指定します。`'student.csv'` は `student.csv` という名前のファイルのみをインポートすることを意味します。

4. インポート結果を確認します。

   ```sql
   SELECT * FROM student;
   ```

   実行結果は次のとおりです：

   ```sql
   +------+------+-------+
   | id   | name | score |
   +------+------+-------+
   |    1 | lin  |    98 |
   |    2 | hei  |    90 |
   |    3 | ali  |    95 |
   +------+------+-------+
   3 rows in set
   ```

#### 例外処理

`LOAD DATA FROM FILES()` ステートメントはエラー診断モードをサポートしており、最初のエラーで操作全体が終了する代わりに、失敗した行を記録することができます。通常のインポートステートメントの後に `LOG ERRORS` 句を追加することで、エラー診断機能を有効にできます。

**例：**

```sql
LOAD DATA FROM FILES(
    LOCATION = '/home/admin/test_data/',
    FORMAT = (
        TYPE = 'csv',
        FIELD_DELIMITER = ','),
    PATTERN = 'student.csv')
    INTO TABLE student
    LOG ERRORS
        INTO '/home/admin/error_logs/'
        REJECT LIMIT 10
        BADFILE '/home/admin/bad_files/';
```

**説明：**

* `LOG ERRORS`：エラー診断モードを有効にします。
* `INTO`：エラーログの保存ディレクトリを指定します。
* `REJECT LIMIT`：許容される最大エラー行数です。`10` は、最大10行のデータインポート失敗を許容し、その制限を超えた場合にインポート操作全体が終了することを意味します。
* `BADFILE`：失敗したデータ行を保存するディレクトリを指定します。

`READ_ERROR_LOG()` 関数を使用してエラーログを確認できます：

```sql
SELECT * FROM READ_ERROR_LOG('/home/admin/error_logs/');
```

### 方法2：INSERT INTO ... SELECT FROM FILES()を使用する

1. データファイルを準備し、サーバーからアクセス可能な場所に配置します。

   1. サーバー上にデータファイルのディレクトリを作成し、テストデータを準備します（以前に作成済みの場合はこの手順をスキップできます）：

        ```shell
        mkdir -p /home/admin/test_data
        ```

   2. `student.csv` ファイルを作成します（ファイルが既に存在する場合はこの手順をスキップできます）：

        ```shell
        vi /home/admin/test_data/student.csv
        ```

   3. ファイルに以下の内容を追加します：

        ```csv
        1,lin,98
        2,hei,90
        3,ali,95
        ```

2. ターゲットテーブルを作成します。

   ```sql
   CREATE TABLE student (id INT, name VARCHAR(50), score INT);
   ```

3. `INSERT INTO ... SELECT FROM FILES()` ステートメントを使用してデータをインポートします。

   ```sql
   INSERT INTO student
   SELECT * FROM FILES(
       LOCATION = '/home/admin/test_data/',
       FORMAT = (
           TYPE = 'csv',
           FIELD_DELIMITER = ','),
       PATTERN = 'student.csv');
   ```

4. インポート結果を確認します。

   ```sql
   SELECT * FROM student;
   ```

   実行結果は次のとおりです：

   ```sql
   +------+------+-------+
   | id   | name | score |
   +------+------+-------+
   |    1 | lin  |    98 |
   |    2 | hei  |    90 |
   |    3 | ali  |    95 |
   +------+------+-------+
   3 rows in set
   ```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>INSERT INTO ... SELECT FROM FILES()</code> は、同じ <code>FILES()</code> 関数構文を使用しますが、より柔軟なデータ処理機能を提供します。SELECTステートメント内でWHERE、JOIN、集約関数などのSQL機能を使用してデータを処理した後に挿入できます。</p>
</main>

## クライアントからのインポート

クライアントからのインポートは、サーバーからファイルの場所に直接アクセスできない場合に適用されます。データファイルはクライアントのローカルにあり、クライアントツールを使用してファイルを読み取り、サーバーに転送します。

**手順：**

1. ローカルにテストデータファイルを作成します。

   1. ローカルの `/home/admin/test_data` ディレクトリに `test_tbl1.csv` という名前のCSVファイルを作成します。

        ```shell
        vi /home/admin/test_data/test_tbl1.csv
        ```

   2. ファイルに以下の内容を追加します：

        ```csv
        1,11
        2,22
        3,33
        ```

2. クライアントを起動し、ローカルファイルインポート機能を有効にします。

   以下のステートメントを実行して、クライアントツールを使用してseekdbデータベースに接続します。**必ず** `--local-infile` パラメータを追加して、ローカルファイルからのデータ読み込み機能を有効にする必要があります。

   ```shell
   mysql --local-infile -hxxx.xxx.xxx.xxx -P2881 -uroot -p****** -Dtest
   ```

   <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>LOAD DATA LOCAL INFILE</code> 機能を使用する場合、クライアント接続時に <code>--local-infile</code> パラメータを追加する必要があります。これはMySQLクライアントの動作であり、他の方法では変更できません。このパラメータを追加しない場合、<code>LOAD DATA LOCAL INFILE</code> ステートメントの実行時にエラーが発生します。</p>
      <p><code>LOAD DATA LOCAL INFILE</code> 機能を使用するには、この機能をサポートするクライアントツールを使用してください。</p>
   </main>

3. テストテーブルを作成します。

   ```sql
   CREATE TABLE test_tbl1(col1 INT, col2 INT);
   ```

4. クライアントで、`LOAD DATA LOCAL INFILE` ステートメントを実行してローカルのデータファイルを読み込みます。

   ```sql
   LOAD DATA LOCAL INFILE '/home/admin/test_data/test_tbl1.csv'
   INTO TABLE test_tbl1
   FIELDS TERMINATED BY ','
   LINES TERMINATED BY '\n';
   ```

5. テーブル情報を確認します。

   ```sql
   SELECT * FROM test_tbl1;
   ```

   実行結果は次のとおりです：

   ```sql
   +------+------+
   | col1 | col2 |
   +------+------+
   |    1 |   11 |
   |    2 |   22 |
   |    3 |   33 |
   +------+------+
   3 rows in set
   ```
