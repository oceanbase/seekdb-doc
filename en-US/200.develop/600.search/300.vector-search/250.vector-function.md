# Use SQL functions

This topic describes the vector functions supported by seekdb and provides usage notes.

## Considerations

* The following operations will fail with the error `different vector dimensions %d and %d` if the dimensions of the vectors are different.
* If the result exceeds the range of a floating-point number, an error `value out of range: overflow / underflow` will be returned.
* The dense vector index supports L2, inner product, and cosine distance as index distance algorithms. The in-memory sparse vector index supports only inner product as the distance algorithm. For more information, see [Dense vector index](200.vector-index/300.dense-vector-index/100.dense-vector-index-overview.md) and [In-memory sparse vector index](200.vector-index/400.sparse-vector-index/100.in-memory-sparse-vector-index.md).
* The vector index search supports the `L2_distance`, `Cosine_distance`, and `Inner_product` distance functions.

## Distance functions

Distance functions calculate the distance between two vectors, and the specific calculation method varies depending on the distance algorithm.

### L2_distance

The Euclidean distance reflects the distance between the coordinates of the compared vectors, essentially the straight-line distance between two vectors. It is calculated using the Pythagorean theorem applied to the vector coordinates:

![Pythagorean theorem](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%8B%BE%E8%82%A1%E5%AE%9A%E7%90%86.jpg)

The function syntax is as follows:

```sql
l2_distance(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to vector types, parameters can accept any other types that can be strongly cast to vector types, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of that parameter must not contain `NULL`.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, `NULL` is returned.

Example:

```sql
CREATE TABLE t1(c1 vector(3));
INSERT INTO t1 VALUES('[1,2,3]');
SELECT l2_distance(c1, [1,2,3]), l2_distance([1,2,3],[1,1,1]), l2_distance('[1,1,1]','[1,2,3]') FROM t1;
```

The result is as follows:

```shell
+--------------------------+------------------------------+----------------------------------+
| l2_distance(c1, [1,2,3]) | l2_distance([1,2,3],[1,1,1]) | l2_distance('[1,1,1]','[1,2,3]') |
+--------------------------+------------------------------+----------------------------------+
|                        0 |             2.23606797749979 |                 2.23606797749979 |
+--------------------------+------------------------------+----------------------------------+
1 row in set
```

### Cosine_distance

Cosine similarity measures the angular difference between two vectors, reflecting their directional similarity regardless of their magnitudes. The cosine similarity ranges from `[-1, 1]`, where `1` indicates identical directions, `0` indicates orthogonality, and `-1` indicates completely opposite directions.

The calculation method for cosine similarity is as follows:

![Cosine similarity](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E4%BD%99%E5%BC%A6%E7%9B%B8%E4%BC%BC%E5%BA%A6.jpg)

Since a higher cosine similarity value indicates greater similarity, cosine distance (or cosine dissimilarity) is sometimes used as a measure of distance between vectors. Cosine distance can be calculated by subtracting the cosine similarity from 1:

![Cosine distance](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E4%BD%99%E5%BC%A6%E8%B7%9D%E7%A6%BB.jpg)

The cosine distance ranges from `[0, 2]`, where `0` indicates identical directions (no distance), and `2` indicates completely opposite directions.

The function syntax is as follows:

```sql
cosine_distance(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to vector types, parameters can accept any other types that can be strongly cast to vector types, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of that parameter must not contain `NULL`.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, `NULL` is returned.

Example:

```sql

INSERT INTO t3 VALUES('[1,2,3]');
INSERT INTO t3 VALUES('[1,2,1]');
```

### Inner_product

The inner product, also known as the dot product or scalar product, represents a type of multiplication between two vectors. Geometrically, the inner product indicates the directional and magnitude relationship between two vectors. The calculation method for the inner product is as follows:

![Inner product](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%86%85%E7%A7%AF.jpg)

The syntax is as follows:

```sql
inner_product(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to vector types, other types that can be strongly converted to vector types are also accepted as parameters, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of this parameter must not contain `NULL`.

* When using this function with sparse vectors, one parameter can be a sparse vector formatted as a string, such as `c2,'{1:2.4}'`; both parameters cannot be strings.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, the return value is `NULL`.

Here is an example with dense vectors:

```sql
CREATE TABLE t4(c1 vector(3));
INSERT INTO t4 VALUES('[1,2,3]');
INSERT INTO t4 VALUES('[1,2,1]');
SELECT inner_product(c1, [1,2,3]) FROM t4;
```

```shell
|                          8 |
+----------------------------+
2 rows in set
```

### Vector_distance

The `vector_distance` function calculates the distance between two vectors and allows you to select different distance algorithms by specifying parameters.

The syntax is as follows:

```sql
vector_distance(vector v1, vector v2 [, string metric])
```

The `vector v1/v2` parameters are described as follows:

* In addition to vector types, other types that can be strongly converted to vector types are also accepted as parameters, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of this parameter must not contain `NULL`.

The `metric` parameter specifies the distance algorithm. The options are:

* If not specified, the default algorithm is `euclidean`.

* If specified, the only valid value is:

  * `euclidean`: Euclidean distance, which is the same as L2_distance.

  * `manhattan`: Manhattan distance, which is the same as L1_distance.

  * `cosine`: Cosine distance, which is the same as Cosine_distance.

  * `dot`: Inner product, which is the same as Inner_product.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, the return value is `NULL`.

Here is an example:

```sql
CREATE TABLE t5(c1 vector(3));
INSERT INTO t5 VALUES('[1,2,3]');
INSERT INTO t5 VALUES('[1,2,1]');
SELECT vector_distance(c1, [1,2,3], euclidean) FROM t5;
```

The result is as follows:

```shell
+-----------------------------------------+
| vector_distance(c1, [1,2,3], euclidean) |
+-----------------------------------------+
|                                       0 |
|                                       2 |
+-----------------------------------------+
2 rows in set
```

## Similarity functions

Similarity functions measure the similarity between two vectors. A higher value indicates greater similarity. They are the inverse concept of distance functions: higher similarity means a smaller distance. In vector search, you can set a similarity threshold to filter out results that meet the criteria.

### inner_product_similarity

The `inner_product_similarity` function calculates the inner product similarity between two vectors. The calculation method is the same as the `inner_product` function, but the return value represents similarity instead of distance. The conversion formula between `inner_product_similarity` and `inner_product` is: `inner_product_similarity(v1, v2) = (1 + inner_product(v1, v2) / (vector_norm(v1) * vector_norm(v2))) / 2`. The `vector_norm` function calculates the Euclidean norm (magnitude) of a vector, which represents the Euclidean distance between the vector and the origin. For a vector `v = [v1, v2, v3, ..., vn]`, the norm is calculated as: `vector_norm(v) = √(v1² + v2² + v3² + ... + vn²)`.

The syntax is as follows:

```sql
inner_product_similarity(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to vector types, other types that can be strongly converted to vector types are also accepted as parameters, including string types (e.g., `'[1,2,3]'`).
* The dimensions of the two parameters must be the same.
* When a single-level array type parameter is present, the elements of this parameter must not contain `NULL`.

The return value is described as follows:

* The return value is a double value representing the similarity between the two vectors. A higher value indicates greater similarity.
* If any parameter is `NULL`, the return value is `NULL`.

Here is an example:

```sql
CREATE TABLE t12(c1 vector(3));
INSERT INTO t12 VALUES('[1,2,3]');
INSERT INTO t12 VALUES('[1,2,1]');
SELECT inner_product_similarity(c1, [1,2,3]) FROM t12;
```

The result is as follows:

```shell
+---------------------------------------+
| inner_product_similarity(c1, [1,2,3]) |
+---------------------------------------+
|                    0.9999999552965164 |
|                    0.9364357516169548 |
+---------------------------------------+
2 rows in set
```

Or more simply:

```sql
SELECT inner_product_similarity([1,0,0], [0,1,0]);
```

The result is as follows:

```shell
+--------------------------------------------+
| inner_product_similarity([1,0,0], [0,1,0]) |
+--------------------------------------------+
|                                        0.5 |
+--------------------------------------------+
1 row in set
```

### cosine_similarity

`cosine_similarity` computes the cosine similarity between two vectors, reflecting their directional similarity regardless of their magnitudes. The formula is: `cosine_similarity(v1, v2) = 1 - (cosine_distance(v1, v2) / 2)`.

Syntax:

```sql
cosine_similarity(vector v1, vector v2)
```

Parameters:

* In addition to vector types, parameters can accept any type that can be strongly cast to a vector type, such as strings (e.g., `'[1,2,3]'`).
* The dimensions of the two parameters must be the same.
* When a parameter is of a single-level array type, it cannot contain `NULL` values.

Return value:

* The return value is of type double, with a range of `[0, 1]`. A value of `1` indicates that the two vectors are in the same direction, while a value of `0` indicates they are orthogonal. A larger value indicates greater similarity in direction.
* If any parameter is `NULL`, the result is `NULL`.

Example:

```sql
CREATE TABLE t13(c1 vector(3));
INSERT INTO t13 VALUES('[1,2,3]');
INSERT INTO t13 VALUES('[1,2,1]');
```

```shell
+--------------------------------+
|             0.9999999552965164 |
|             0.9364357516169548 |
+--------------------------------+
2 rows in set
```

Or more simply:

### l2_similarity

`l2_similarity` computes the L2 similarity between two vectors. L2 similarity is based on the Euclidean distance, but the returned value represents similarity rather than distance. A higher similarity value indicates greater similarity between the vectors. The conversion to `l2_squared` is: `l2_similarity(v1, v2) = 1 / (1 + l2_squared(v1, v2))`.

* In addition to vector types, parameters can accept any type that can be strongly cast to a vector type, such as strings (e.g., `'[1,2,3]'`).

## Arithmetic functions

Arithmetic functions provide addition (+), subtraction (-), and multiplication (*) operations for vectors, single-level arrays, and special strings. The operations are performed element-wise. For example, addition is calculated as:

![Addition](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%8A%A0%E6%B3%95.jpg)

Syntax:

```sql
v1 + v2
v1 - v2
v1 * v2
```

Parameters:

* In addition to vector types, parameters can accept any type that can be strongly cast to a vector type, including single-level arrays (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`). **Note:** Both parameters cannot be string types; at least one parameter must be a vector or single-level array.

* The dimensions of the two parameters must be the same.

* When a parameter is of a single-level array type, it cannot contain `NULL` values.

Return value:

* If at least one parameter is a vector, the return value is a vector of the same type as the vector parameter.

* If both parameters are single-level arrays, the return value is of type `array(float)`.

* If any parameter is `NULL`, the result is `NULL`.

Example:



**Vector normalization**

Vector normalization (Normalization) is the process of standardizing the length (magnitude) of a vector to 1. The `vector_norm` function is commonly used to implement vector normalization.

For vector indexes using the `l2_distance` distance type, it is recommended to normalize the vectors to improve the accuracy of similarity searches. After normalization, the magnitude of the vectors is 1, and the range of L2 distances is limited to `[0, 2]`, thus avoiding precision issues caused by excessively small similarity values.

For example, for the vector `[3, 4]`:
* The magnitude of the vector: `vector_norm([3, 4]) = √(3² + 4²) = 5`
* After normalization: `[3, 4] / 5 = [0.6, 0.8]`

The magnitude of the normalized vector is 1, which can be verified as follows:

```sql
SELECT vector_norm([0.6, 0.8]);
```
The result is as follows:

```shell
+-------------------------+
| vector_norm([0.6, 0.8]) |
+-------------------------+
|       1.000000029802322 |
+-------------------------+
1 row in set
```

### Vector_dims

The `vector_dims` function is used to return the dimension of the vector.

The syntax is as follows:

```sql
vector_dims(vector v1)
```

The parameters are described as follows:

* In addition to the vector type, other types that can be strongly cast to a vector type are also supported, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

The return value is described as follows:

* Returns the `dims(int64)` value.

* If the parameter is `NULL`, an error is returned.

Here is an example:

```sql
CREATE TABLE t11(c1 vector(3));
INSERT INTO t11 VALUES('[1,2,3]');
INSERT INTO t11 VALUES('[1,1,1]');
SELECT vector_dims(c1), vector_dims('[1,2,3]') FROM t11;
```

The result is as follows:

```shell
+-----------------+------------------------+
| vector_dims(c1) | vector_dims('[1,2,3]') |
+-----------------+------------------------+
|               3 |                      3 |
|               3 |                      3 |
+-----------------+------------------------+
2 rows in set
```

## Semantic index-related functions

In addition to the general vector functions mentioned above, seekdb provides vector search functions specifically for semantic indexes (vector indexes created on text columns):

* `semantic_distance(column_name, 'query_text')`: Performs vector search using the original text. The system automatically calls the embedding model to convert the text into a vector.
* `semantic_vector_distance(column_name, query_vector)`: Performs search using the vector, supporting both index search (with the `APPROXIMATE`/`APPROX` clause) and full-table scan (without the `APPROXIMATE`/`APPROX` clause).

These two functions are specifically used for semantic index scenarios. For more details and examples, see [Semantic index](../400.semantic-search.md).
